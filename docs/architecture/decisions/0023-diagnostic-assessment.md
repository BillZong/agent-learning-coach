# ADR-0023: 诊断评估——映射、汇总与降级

- 状态：已接受
- 日期：2026-11-25

## 背景

Topic 22 的工程问题是：**诊断结果如何映射到知识点？当题目与知识点的映射缺失
时，系统应该如何降级？**

ADR-0020 定了「判定」（会 / 不会 / 未判定）与它的准入条件，ADR-0021 定了题目
怎么生成。但两者之间有一段没建：**题目 → 作答 → 判定**这条链，以及映射缺失
时的处理。

Plan.md 的 Day 22 清单：研究知识点映射 / 研究诊断证据与能力估计 / 实现诊断结果
评估 / 实现题目与 Knowledge Point 映射 / 实现诊断结果汇总 / 保存诊断证据 / 编写
Assessment Tests / 交付 Diagnostic Assessment Engine。

实现前的代码里有**三个具体缺口**（都是评审时读代码发现的，不是推测）：

1. **「映射缺失」无法表达。** ``DiagnosticExercise.point_id`` 是必填的
   ``KnowledgePointId``。于是「这道题不知道考哪个知识点」这件事**在模型里没有
   位置**——只能靠「所有题都必须绑定」的约定把它藏起来。而题目可能来自外部题库、
   历史数据或跨课程题，这些题确实不知道（或不该由本课程决定）它考哪个点。
2. **判定与依据可以不自洽。** 构造 ``DiagnosticVerdict(point_id=k2, basis=<k1 的题>)``
   不会报错。「判定说 k2 会，依据却指向 k1」是自相矛盾的事实，但模型允许它。
3. **「对错」是手填的。** ``DiagnosticSubmission.correct: bool`` 由调用方直接填
   进来。它让「作答」同时承载了事实（答了什么）与判断（对不对），而判断的依据
   （谁判的、依据什么）无处安放；更要命的是它可以被随手填成 ``True``。

Phase 1 没有主教材章节，评估建模由本项目自己定。

## 决策

**映射由题目声明；判定由外部判官给出；证据保留全部；映射缺失走「不判定但保留
并报告」的降级。**

### 1. 映射是「题目 → 知识点」，由题目自己声明

``DiagnosticExercise.point_id`` 表示这道题考哪个知识点。它**可空**——``None``
就是**映射缺失**。

不由评估环节推断映射，理由：推断出的映射无法审计。诊断结论要能回答「为什么
判定这个知识点会」，如果映射是猜的，这条链就断了。

### 2. 判定是外部判断：判官协议

```python
class Grader(Protocol):
    def grade(exercise, submission) -> Grading: ...
```

``Grading`` 是三态：``correct`` / ``incorrect`` / ``undecided``。

**领域层定义「需要判官给出什么」，不规定怎么判。** 精确匹配是一种实现
（``ExactMatchGrader``），LLM 判官是另一种（Topic 41）。换判官不需要改领域
模型——这与 ADR-0002 的 ``LLMClient`` 协议是同一个做法。

**``undecided`` 是一等状态**，不是「当成答对或答错」：开放题没有唯一答案，
精确匹配判不了。把它算作答错会**凭空制造知识缺口**，算作答对会**掩盖缺口**。
判不了就说判不了——它对应 ADR-0020 的 ``unknown`` 判定。

### 3. 作答只承载事实

``DiagnosticSubmission`` 去掉 ``correct``，只留「答了什么」。对错移到
``DiagnosticEvidence.grading``，由判官产生。

理由：作答是**事实**，判断是**判断**。让一个字段同时承载两者，等于让「学习者答
错了」这种判断可以被随手填写，而它的依据无处安放。

### 4. 证据是判定与覆盖的共同凭据

``DiagnosticEvidence`` = 题目 + 作答 + 判定结论 + 归属的知识点。

**判定携带证据**（``DiagnosticVerdict.evidence``，可多条）：一个知识点出多道题
时，每道题的作答都是一份依据。原来的 ``basis`` 只能放一道题或一次作答，多题
场景下会丢掉其余依据。

**判定与依据必须一致**：判定 k2 不能拿 k1 的证据。这条在构造期校验——
自相矛盾的事实不该等到展示时才发现。

**诊断保留全部证据**（``Diagnosis.evidence``），不只是支撑了判定的那些：
映射缺失的作答也是事实（学习者确实答了这道题），丢掉它就没法回答「这次诊断到底
覆盖了什么」。

### 5. 汇总规则：全部答对才算会

一个知识点的所有证据：

| 情况 | 判定 |
| ---- | ---- |
| 全部答对 | 会 |
| 有一道答错 | 不会 |
| 没有证据 / 只有「判不了」 | 未判定 |

**为什么不是「有一道答对就算会」**：诊断的目的是**找出要补的地方**，而不是给出
尽量好的评价。宽松的汇总会把「侥幸答对一道」当成掌握，计划因此跳过真正没学会
的知识点——而知识点之间有先修依赖（ADR-0016），跳过一处会让后面全部塌掉。
严格汇总的代价是「多教一点」，那只是浪费一点时间。

### 6. 降级：映射缺失 → 不判定，但保留并报告

映射缺失的作答：

- **不进入判定汇总**——它不指向任何知识点，不能支撑任何结论；
- **保留为证据**——它是事实；
- **进入降级报告**（``DegradationReport``）——让调用方知道「这次诊断有东西没
  覆盖到」。

降级**不抛异常**：它是一次诊断的**正常结果**（题目可能来自外部题库），不是失败。
调用方据此决定补题、忽略还是人工处理。

**降级与错误是两件事**：

| 情况 | 处理 |
| ---- | ---- |
| 映射缺失（题目没声明考点） | **降级**：不判定、保留、报告 |
| 判不了（开放题） | **降级**：判「未判定」，保留、报告 |
| 判定与依据不一致 | **错误**：模型自相矛盾，构造期拒绝 |
| 作答引用不存在的题目 | **错误**：数据不一致，拒绝 |
| 题目标识重复 | **错误**：配对变得含糊，拒绝 |

前两行是「信息不全」，后三行是「信息矛盾」。把它们混为一谈，要么让矛盾悄悄
通过，要么让正常情况不断报错。

### 7. 归一化规则共用一份

精确匹配用 ``core.text.normalize_for_match``（折叠空白、忽略大小写与标点），
与计划判重用同一条规则。两处各写一份必然漂移——``core/agent/planning.py`` 的
``normalize_content`` 改为委托给它。

## 后果

- 好处：映射缺失成为**可表达的状态**而不是隐藏的约定；判定与依据的一致性被
  强制；「对错」由判官给出而非手填；证据完整保留，「诊断覆盖了什么」可回答；
  换判官（LLM 判官）不需要改领域模型。
- 代价：**``DiagnosticSubmission`` 与 ``DiagnosticVerdict`` 的形状变了**
  （去掉 ``correct`` / ``basis`` / ``basis_kind``，改为 ``evidence``）。所有调用
  方在本主题内完成切换。
- 代价：**``EvidenceKind`` 暂时没有真正的用途**。Phase 1 只有做题这一种证据来源，
  自述与外部证据的采集流程尚未存在。枚举保留（它是 ADR-0020 已定的概念），但
  「依据是什么」现在由证据对象本身回答。
- 风险：**严格汇总会高估缺口**。一道题的偶然失误就把知识点判成不会，计划因此
  多教。这是刻意选的偏差（漏教比多教危险），但缺阈值机制——「一个知识点出几道
  题才算判准」需要实证（Topic 46）。
- 风险：**精确匹配只适用于有唯一答案的题目**。开放题在 Phase 1 只能判
  ``undecided``，除非引入 LLM 判官（Topic 41）。因此 Phase 1 的诊断覆盖能力
  受限于客观题。
- 边界：能力估计（连续掌握度）属于掌握度模型（Topic 43）；证据的多种类型与置信
  权重属于证据型评估（Topic 42）；LLM 判官属于 Topic 41。

## 补充说明（2026-11-25）

实现中确认的事实：

1. **「映射缺失」不能靠约定表达。** 评审时读代码发现 ``point_id`` 是必填的，
   于是「题目不知道考哪个点」这件事在模型里没有位置。改成可空后，降级才有
   对象可降——**降级策略需要一个能表达「缺失」的模型，否则只能靠约定**。
2. **「判定」与「依据」可以不自洽，而且没人会发现。** 构造一个指向别的知识点的
   依据不会报错，直到展示时才看出问题。构造期校验把它挡住。
3. **手填的 ``correct`` 是个洞。** 它让判断可以被随手填成 ``True``，而判断的
   依据无处安放。去掉它之后，「谁判的、依据什么」变成判官与证据的事——判断的
   归属被显式化。
4. **汇总的宽严是有后果的选择。** 「有一道答对就算会」看起来友好，但会让计划
   跳过真正没学会的知识点；知识点有先修依赖（ADR-0016），跳过一处会让后面全部
   塌掉。严格汇总的代价只是多教一点。
5. **降级与错误必须分开。** 映射缺失与开放题是**信息不全**（正常结果），判定与
   依据不一致、作答引用不存在的题是**信息矛盾**（数据坏了）。混为一谈要么让
   矛盾悄悄通过，要么让正常情况不断报错。
6. **「判不了」是真实状态，不是失败。** 开放题没有唯一答案，精确匹配判不了；把它
   算作答错会凭空制造知识缺口。``undecided`` 让「不知道」与「不会」分开——这与
   ADR-0020 的 ``unknown`` 是同一个道理，只是落到了证据层。
