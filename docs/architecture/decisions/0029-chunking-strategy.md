# ADR-0029: 切分策略——按材料类型选，以及参数如何被测试锁定

- 状态：已接受
- 日期：2026-11-26

## 背景

Day 28（Phase 2 · AI Tutor）的工程问题是：**讲义、代码、习题等不同文档类型，应采用
何种切分策略？切分参数如何被测试锁定？**

Phase 0–1 已有的相关零件：

- `core.rag.chunking`（Day 11）：`FixedSizeChunker`（定长，主教材 5.3.2 的做法）与
  `RecursiveChunker`（按结构递归，不切断语义单元）；`chunk_id(document_id, index)`
  让切片 id 可复现；
- `core.rag.types.Chunk`：切片带 `metadata`，**参与检索过滤**；
- 课程文档（ADR-0028）：`CourseDocument` 带 `kind`（讲义 / 习题 / 代码 / 笔记本 /
  参考资料 / 其它）与 `point_ids`（覆盖的知识点）；
- `core.application.ingestion.to_rag_document`（Day 27 之后）：课程文档 → 可检索文档，
  课程侧的元数据进 `metadata`。

Plan.md 的 Day 28 清单：研究 Chunking Strategy / 对比固定长度和语义切分 / 研究
Chunk Metadata / 实现 Fixed-size Chunking / 实现 Recursive Chunking / 保存 Chunk
Metadata / 对比不同策略的检索结果 / 建立 Chunking Tests / 交付 Chunking Module。

## 决策

**按材料类型选策略；结构由正则给出；参数集中在一处；测试锁不变量，不锁数字。**

### 1. 按材料类型选策略

一刀切的策略总有一半材料是错的：**每类材料有它自己的语义单元**。

| 材料类型 | 切分器 | 语义单元 |
| -------- | ------ | -------- |
| `notes` 讲义 | `RecursiveChunker` | 段落 / 句子 |
| `exercise` 习题 | `ExerciseChunker` | 一道题（含答案说明） |
| `code` 代码 | `CodeChunker` | 一个顶层定义（函数 / 类） |
| `notebook` 笔记本 | `RecursiveChunker` | 单元（摄取时以空行分隔） |
| `reference` 参考资料 | `FixedSizeChunker` | 固定长度（结构不规则） |
| 其它 | `RecursiveChunker` | 兜底 |

`PolicyChunker` 从 `document.metadata["kind"]` 取种类，取不到就用兜底。

**为什么代码按顶层定义切**：一个函数或一个类是完整的语义单元，按字符切会把它们
切碎——碎片检索不到，也读不懂。**为什么习题按题号切**：题干、选项、答案说明属于
同一题；切碎之后模型据此回答会答非所问。

### 2. 结构由正则给出，不为每种语言写一个切分器

`CodeChunker.pattern` 默认匹配 Python 的 `def` / `class` / `async def`；
`ExerciseChunker.pattern` 默认兼容 `1.` `1、` `1)` `第1题`。换语言、换教材改正则即可。

**结构识别失败就退回兜底**（按段落 / 句子的递归切分）：识别不出来时**切得差一点**
好过**切不出来**。

### 3. 超限兜底不是妥协，是兜底

一个巨大的函数仍然要切得开：超出上限的部分交给兜底切分器。**正常路径按结构切，
只有超限时才退到通用策略**——这与「先试专用方案，失败再退通用方案」是同一条。

### 4. 参数集中在一处

`default_chunking_policy()` 是**唯一一处数字的所在地**。散落的默认值迟早漂移
（每个切分器各有自己的 `size=500`，改一处要改三处，而且没人知道改了什么）。

### 5. 测试锁不变量，不锁数字

**这是本主题最重要的一条。** 切分参数（块大小、重叠）会随模型与语料变化；**语义
单元的完整性不会**。因此测试断言的是：

| 不变量 | 含义 |
| ------ | ---- |
| 讲义不切断句子 | 切片以完整句号 / 标题结尾 |
| 代码不切断顶层定义 | `class Calculator:` 与它的方法在同一个切片里 |
| 习题不切断一道题 | 答案跟着题走 |
| 切片不超上限 | 包括代码与习题 |
| 切片 id 可复现 | 同一份文档的第 N 块永远同一标识 |
| 元数据被保留 | 课程 id 与知识点关联在切片上 |
| 切分是幂等的 | 同一份文档切两次结果一样 |

**锁数字只会让改动变成「改测试」**——测试成了数字的橡皮图章，改参数就得改断言，
于是断言失去意义。

### 6. 课程文档 → 可检索文档

`to_rag_document(course_document)` 把课程文档变成带课程元数据的 RAG 文档：

```python
metadata = {"kind": ..., "course_id": ..., "title": ..., "point_ids": [...]}
```

**材料只解析一次**：课程侧记「属于哪门课、覆盖哪些知识点」，RAG 侧记「切成什么样、
嵌成什么向量」。元数据进 `metadata` 后，切片天然带上它们（切分器复制文档的
metadata），检索时就能按课程与知识点过滤（Day 30）。

### 7. 切片 id 可复现（沿用）

`chunk_id(document_id, index)`：同一份文档的第 N 块永远得到同一标识，因此重新切分
是覆盖而不是追加（ADR-0011 的摄取幂等性同理）。

## 补充说明（2026-11-27）

**超限单元怎么办**——「既不超上限又不破坏结构」是做不到的：单个语义单元超过上限
时，二者必居其一。**上限是硬不变量**（检索质量与上下文预算都依赖它），所以
**破坏结构有时不可避免**。

但**降级不该是静默的**：被迫拆开的单元，其切片带 `oversized_unit` 标记——否则下游
看到的是一块「看起来完整」的碎片，却不知道它是残缺的。

（这条是 Day 27–30 复盘时关掉的遗留：「超限时怎么切才能既不超上限又不破坏结构」。）

## 后果

- 好处：不同材料用各自的语义单元切分；切片带得上课程与知识点元数据；参数只有一
  处；测试保护的是**行为**而不是数字，因此改参数不会让测试失去意义。
- 代价：**正则的通用性有限**。别的语言的代码、别的教材的题号写法要改正则。
- 代价：**数字仍然没有实证依据**。800 / 1200 / 1000 只是起点——真正的取值要靠检索
  评估（Day 30）与真实语料。
- 代价：**课程文档与切片各存一份内容**（承接 ADR-0028 的同一个取舍）。
- 风险：**结构识别漏判**。题号写法 unusual 的习题会退回兜底切分——切得差一点，
  但不会切不出来。若这类材料很多，应该改正则而不是改切分器。
- 风险：**「按类型选策略」的价值未经检索评估验证**。本主题只证明了「切分边界对
  了」（不变量），没证明「检索效果更好了」——那要等 Day 30 的评估集。
- 边界：**切分策略的评估**属 Day 30（检索评估）；**按 token 计预算**不在本主题
  （切分器不该依赖分词器，ADR-0008）；**上下文裁剪**属 Day 30。

## 补充说明（2026-11-26）

实现中确认的事实：

1. **一刀切的策略不是「简单」，是「一半错」。** 定长切分代码会把函数拦腰截断；
   递归切分（按段落）**对代码也不对**——段落不是代码的语义单元。前者要按顶层定义
   切，后者要按题号切。**每类材料有它自己的语义单元**，这是本主题的出发点。
2. **测试锁不变量，不锁数字。** 数字会随模型与语料变化；「代码不切断顶层定义」不会。
   锁数字的测试在参数一改就变成「改测试」——断言从此只是橡皮图章。
3. **结构识别失败要能退。** 题号写法 unusual 的习题、不是 Python 的代码——识别不
   出来时退回通用切分，**切得差一点好过切不出来**。识别规则是可调的（正则），
   切分器本身不用改。
   切片要按「教 k1 时」「这门课」过滤，就必须把课程 id 与知识点关联带在切片上。
   课程 id 与知识点关联带在切片上。课程文档 → RAG 文档的桥（`to_rag_document`）
   就是干这个的——**材料只解析一次，两边共用**。
