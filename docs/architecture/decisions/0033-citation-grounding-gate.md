# ADR-0033: 引用支撑的处置——门禁放在应用层，评估用词面口径

- 状态：已接受
- 日期：2026-11-27

## 背景

Day 31（Phase 2 · AI Tutor）的工程问题是：**引用如何保证生成内容可溯源？当引用与原文不符时，应该由哪一层拦截？**

Day 12（ADR-0012）已经交付了**引用机制**：`Citation`（指向具体切片）、`CitationSet`、
`CitationRegistry`（标记稳定）、`CitationValidator`（三类检查）。但它**只给报告，
不做决定**——「这段答案能不能给学习者看」至今没有答案。

而 Day 30 之后，项目的习惯已经定下来了：**没有量的机制只能靠感觉调**。引用这一侧
一直没有对应的量（Day 30 给检索做了召回、MRR、找全率、假阳性率）。

所以本 ADR 做两件事：**把处置策略定下来**（应用层的门禁），**把引用质量量出来**
（评估集 + 指标）。

## 研究

### 1. 文献里的两个维度：**attribution** 与 **citation** 不是一回事

《Attribution, Citation, and Quotation: A Survey of Evidence-based Text Generation
with LLMs》（arXiv:2508.15396，134 篇论文 / 300 个指标）把评估分成维度：

| 维度 | 问什么 | 主流方法 |
| ---- | ------ | -------- |
| **Attribution** | 内容能不能追溯到证据（**不要求**显式引用） | **NLI 蕴含**（ALCE 的 citation NLI） |
| **Citation** | 引用**对不对**（指向正确的来源）与**全不全**（该引的都引了） | **检索式**（用 gold standard 算 precision / recall / F1） |

**这个区分对本项目很关键**：本项目的校验器查的是「**引用指向的东西必须真的存在**」
（编造）与「引用的切片和这句话有词面交集」（可能指错）——它落在 **citation** 这一侧，
而**不做 attribution**（不判断「这段说法本身是不是材料支持的」）。

### 2. 主流做法用 **NLI 蕴含**，本项目用**词面交集**

ALCE（Gao et al. 2023）的 citation NLI 用蕴含模型判断「这句话是否被引用的材料
支撑」，算 precision / recall / F1。文献里的另一条线（Auto-AIS、FActScore）把答案
拆成 atomic facts 逐条验证。

**本项目没有 NLI 模型**，用的是词面交集（`core.text.tokenize`，中文二元组）。
**词面支撑是蕴含的必要不充分条件**——共享词不等于支撑。

### 3. 引用风格与证据粒度：本项目选的是主流那一档

- **引用风格**：inline 标记（`[1]`）占 60%+ ✓——本项目就是 inline ✓；
- **证据粒度**：段落级（chunk）占 40%，文档级 43%，句子级 12% ✓——本项目是
  chunk 级 ✓；
- **每个论断多个引用**是多数做法 ✓——本项目的引用集合天然支持 ✓。

### 4. 幻觉风险与「没有引用」的处置

文献的共识：**编造引用比没有引用更危险**（ADR-0012 已经这么判 ✓）。没有引用只是
「没有依据」；编造引用是「假装有依据」，会让读者去核对一段根本不存在的材料。

而**没有引用不等于错**：讲通用概念时，模型用自己的知识回答是合理的。

## 决策

### 1. 支撑门禁在**应用层**，策略由调用方给

**领域层不选边**（ADR-0020/0024 的老规矩）：判定与处置之间需要显式衔接。
`core.rag.citation` 负责**判定**（它只给报告），`core.application.grounding`
负责**处置**（它给决定），策略（`GroundingPolicy`）由调用方按业务给 ✓。

### 2. 三档判定 + 两道可配的闸

| 判定 | 含义 | 默认处置 |
| ---- | ---- | -------- |
| `grounded` | 有引用，且都存在 | 交付 |
| `ungrounded` | 一个引用标记都没有 | 交付（**警告**） |
| `fabricated` | 引用了不存在的标记 | **拦截** |

两道闸都可配：

- `block_on_fabrication`（默认 True）：编造的引用是否拦住答案；
- `require_citation`（默认 False）：是否要求答案必须带引用——**教通用概念不需要，
  问「材料里怎么写的」需要** ✓。

### 3. 拦截时**不给原文**：重试指令 + 兜底话术

**这是本 ADR 最容易被做错的一处**。直觉上「拦截 = 不给」，但「不给」有两种做法：

- 给原文 + 一句「这条引用有问题」✗——**那段文字里有编造的引用，递过去就是递假引用**；
- 给兜底话术（「我在材料里没找到支持这一点的依据」）+ 一条**重试指令**给模型 ✓✓。

**严格门禁的失败模式是沉默**——所以拦截必须配一条能继续走的路：重试。重试指令要
具体（「只引用检索结果里出现过的标记；材料里没有依据时，直接说没有找到依据」），
否则模型会再编一次 ✓。

### 4. 引用评估：**词面口径**，指标分两半

`core.rag.citation_evaluation` + `evals/citations.json`（12 条用例）。

**第一半：校验器准不准**（用人工标注）——

| 指标 | 问什么 |
| ---- | ------ |
| **校验器准确率** | 判定与标注**完全一致**的用例比例（多报与漏报同样算错） |
| **校验器精确率** | 校验器报出的问题里有多少是真的 |
| **校验器召回率** | 真问题里有多少被查出 |

**第二半：答案的引用质量**——

| 指标 | 问什么 |
| ---- | ------ |
| **引用精确率** | 答案里的引用中，有多少撑得起来（**上界估计**：词面口径） |
| **引用覆盖率** | 带引用的句子占全部句子的比例 |
| **编造率** | 答案里的引用中，有多少指向不存在的标记 |

**实测（12 条用例）**：校验器准确率 **0.92**、精确率 **1.00**、召回率 **0.83**；
引用精确率 0.62、覆盖率 0.81、编造率 0.23。

### 5. 词面口径有**假阴性**——而修它需要更大的评估集

漏掉的那一条：答案「装饰器可以把返回值乘以二[1]」引用的是闭包那段的文字——
**答案与切片只共享「返回」两个字**，词面判定就算「支撑」了 ✓✓。

**共享词不等于支撑**——这就是词面口径的假阴性。

**修法**（提高重叠门槛，比如至少共享两个词或按比例）是显然的，**但现在不做**：
12 条用例**定不出一个门槛**——Day 30 的教训是「评估集太小时，对比是空的」。门槛
必须等评估集变大、且真嵌入与真模型就位之后再定 ✓。

## 后果

- 好处：**「能不能交付」有了答案**，且答案可配、可测；引用质量第一次有量；
  **拦截时不会把假引用递给学习者**；拦截配了重试路径，不会沉默。
- 代价：**词面口径的引用精确率是上界估计**——它不是真值，不能当「引用有多准」对外说。
- 代价：**评估集是人工合成的**——量的是机制，不是真实模型的引用习惯。
- 代价：**默认拦截会让一部分答案被重试**——延迟变长（一次模型调用）。
  这是「假装有依据」的代价，值不值得由策略决定。
- 风险：**阈值调不好会误伤**——词面口径放宽会漏报（已实测），收紧会误报。
  门槛需要数据来定，不能拍脑袋。
- 边界：**NLI 蕴含判定不做**（要额外模型与依赖）；**真实模型的引用质量待有**；
  **attribution（说法本身是否被支撑）不做**——那是模型的事，本项目只做 citation
  这一侧。

## 补充说明（2026-11-27）

实现中确认的事实：

1. **「拦截」不等于「不给」**。第一版把被拦的答案连同补救话术一起渲染——
   **学习者照样看见了那个编造的引用**。现在被拦时只给兜底话术，原文留在内部 ✓。
   **拦截的语义是「不交付」，不是「打个折扣交付」** ✓。
2. **补救话术与重试指令是两件事**。给学习者的是「我没找到依据」（诚实）；
   给模型的是「只引用出现过的标记，没有依据就说没有依据」（可执行）✓。
3. **评估集第一版有一条标注错了**（「既没有引用、也没有引用集合」那条的答案里其实
   带了一个标记）——它让校验器准确率从 0.92 掉到 0.83。**评估集的 bug 会伪装成
   机制的问题**——所以每条用例的标注都要自己核一遍 ✓。
