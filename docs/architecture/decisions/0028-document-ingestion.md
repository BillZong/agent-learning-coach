# ADR-0028: 课程文档摄取——格式、部分成功与幂等

- 状态：已接受
- 日期：2026-11-26

## 背景

Day 27（Phase 2 · AI Tutor）的工程问题是：**课程文档导入支持哪些格式？导入失败
时应整批回滚，还是允许部分成功？**

Phase 1 已有的相关零件：

- `core.rag.loader`（Day 11）：`TextFileLoader` / `DirectoryLoader`，只支持纯文本与
  Markdown，**并明确写着「PDF、Word 等富格式的解析留给 Day 27」**；
- `core.rag.ingestion`（Day 11）：「把一个目录变成可检索的向量库」，且**已经定了
  一个口径**——「摄取不吞错：读不了的文件被跳过并记录原因，而不是让整批摄取失败
  ——一份坏文件不该毁掉整个课程库」；
- `core.learning.domain.Course`（ADR-0016）：课程聚合拥有知识结构；
- 持久化基线（ADR-0026）：形状 / 协议 / 实现三层分开，`migrations/` 放 DDL。

Plan.md 的 Day 27 清单：研究 Document Ingestion / 研究常见文档解析方式 / 定义
Course Document / 实现 Document Loader / 实现文档元数据 / 实现文档持久化 / 实现
基础错误处理 / 交付 Course Document Ingestion。

## 决策

**支持文本、Markdown、代码、PDF、笔记本；部分成功但失败必须进报告；摄取幂等；
课程文档是独立实体，id 由来源推导。**

### 1. 课程文档是独立实体，不是 ``Course`` 聚合的一部分

`CourseDocument` 有自己的 id，按 ``course_id`` 引用课程——**跨聚合只按 id 引用**
（ADR-0015）。

理由：导入一份材料不该**重写整门课**（那正是「一次事务只改一个聚合」要避免的），
而材料的生命周期（导入、覆盖、失效）与课程本身也不同。

### 2. 它与 RAG 的 ``Document`` 是什么关系

| | RAG ``Document`` | 课程文档 |
| -- | --------------- | -------- |
| 是什么 | 检索的**原料** | 材料的**课程侧记录** |
| 回答什么 | 这段文字是什么 | 这门课有哪些材料、覆盖哪些知识点 |
| 会被 | 切分、嵌入、进向量库（Day 28–31） | 存库、标注知识点 |

**同一个文件被两边各记一份，但解析只做一次**——加载器在 ``core.rag.loader``，
课程侧只加「属于哪门课、覆盖哪些知识点」。

### 3. 格式：文本 / Markdown / 代码 / PDF / 笔记本

| 格式 | 解析 | 说明 |
| ---- | ---- | ---- |
| ``.txt`` ``.md`` ``.markdown`` ``.rst`` | 纯文本 | 已有 |
| ``.py`` ``.pyi`` | 纯文本 | 代码按原文保存；**切分策略是 Day 28 的事** |
| ``.pdf`` | PyMuPDF 逐页取文本 | 扫描件（纯图片）取不到文本 → **跳过并记录**，不产出空文档 |
| ``.ipynb`` | 取代码单元与 Markdown 单元 | 输出与执行结果无关——那是运行产物，不是材料 |
| 其它 | — | **不支持的格式明确失败**（不是「读不了」） |

**Word（``.docx``）不做**：``python-docx`` 只在 notebook 依赖组里，把它提到主依赖
是为一个还没验证有需求的格式增加重量。等真有 PDF 之外的富格式需求再评估。

**「不支持的格式」与「读不了的文件」是两回事**，但两者都不该让整批摄取失败。

### 4. 部分成功，但失败必须进报告

沿用 RAG 侧已有的口径：**一份坏文件不该毁掉整个课程库**。

但**静默的部分成功比整批失败更糟**——它让人以为材料齐了。因此报告里必须有失败
清单：哪几份没进来、为什么。

「整批回滚」只在一种情况下成立：**前置条件错误**（课程不存在）。那是调用方的
错误，不是某份材料的问题——「课程都没有」时没法谈「导入了哪些材料」。

### 5. 摄取是幂等的

文档 id **由来源推导**（与 ``core.rag.loader.document_id`` 同一套算法）：同样的材料
每次导入得到同样的 id，因此重复导入是**覆盖**而不是追加。这让「换了教材重新导入
一遍」成为安全的日常操作。

**内容没变就不写**（避免无谓的版本递增）；内容变了才更新。

### 6. 知识点关联不会被顺手抹掉

重新导入更新的是**材料本身**（正文、标题、种类）；**关联是课程侧的标注**，只有
请求显式给出时才改：

| 请求里的 ``point_ids`` | 语义 |
| ---------------------- | ---- |
| ``None``（不给） | **不改**——保留现有的关联 |
| ``()``（空元组） | **清空** |
| 非空 | **设置**为这些知识点 |

「三种语义而不是两种」是为了让「清空」可表达——只有「给 / 不给」时，「不给」就
没法区分「保持」与「清空」。

### 7. 材料属于一门课

同一份材料（同一个 id）被导入到**另一门课**会被**拒绝并报告**：材料在整个系统里
只有一个身份，课程归属是它的属性，不是它的多份副本。

一门课被多个学习者共用**不受影响**——课程是共享的，学习者的进度才是分片的
（ADR-0018）。

### 8. 一致性问题只报告，不阻止导入

关联到**不存在的知识点**时，报告里记一条 issue，但材料照样进来：材料本身是好的，
只是标注错了。挡住整份材料会让人以为「这份材料不能用」，而实际上它只是「关联错
了」——这与 ADR-0017 的做法一致（一致性问题成批报告，不逐个抛异常）。

### 9. 正文可以有首尾空白

领域层有一条「字段不允许首尾空白」的规则（ADR-0015 时期定的：空白是调用方的错
误）。**那条规则是给标识符与短标签用的**——文件末尾通常有换行，正文按原样保存
才是对材料的忠实。因此 `CourseDocument.content` 只校验「不是空白」。

## 后果

- 好处：课程材料有了第一等的领域表示；摄取幂等（重导一遍是安全操作）；失败看得见；
  解析只做一次，两边共用；富格式（PDF、笔记本）能进课程库。
- 代价：**解析与领域记录各存一份内容**（RAG 侧一份、课程侧一份）。这是刻意的：
  两边的形状与生命周期不同（切片 vs 文档），强行合并会让两边都别扭。
- 代价：**知识点关联靠调用方给**。本主题不做自动关联（判断「这份材料讲的是哪个
  知识点」要模型打分，属 Topic 46 的范畴）。
- 代价：**Word 不支持**；扫描版 PDF 取不到文本。
- 风险：**课程归属冲突只能报错**。一份材料想进两门课，目前没有「引用同一份材料」
  的机制（那需要「材料」与「课程材料的关系」分成两个对象）。
- 风险：**正文存两遍**（课程侧 + 切片侧），存储翻倍。材料量小时无所谓。
- 边界：**切分策略**（讲义 / 代码 / 习题要不要用不同的切法）属 Day 28；**知识点
  自动关联**属 Topic 46；**从 URL 导入**（抓取网页）没做；**文档的历史版本**没做
  （当前是覆盖，材料的历史不保留）。
- 边界：**SQL 适配器**仍未实现（ADR-0026 的缺口）；`migrations/0002` 只在真实
  PostgreSQL 上验证过 DDL，适配器还没写。

## 补充说明（2026-11-26）

实现中确认的事实：

1. **「不允许首尾空白」这条规则不能套在正文上。** 实现时撞上了：领域层那条规则
   来自「标识符的空白是调用方的错误」，而**文件末尾通常有换行**。正文按原样保存
   才是对材料的忠实，因此 `content` 只校验「不是空白」。**规则要按字段的语义分**，
   不是一律套用。
2. **负载信封的 ``kind`` 键会撞名。** 课程文档自己也有一个「种类」字段（讲义 /
   习题 / 代码），与信封的类型标记同名——后者被前者覆盖，解码时报「负载种类是
   'notes'」。改成 ``document_kind``。**教训：信封的键要是保留字。**
3. **「不支持的格式」与「读不了的文件」必须分开报。** 两者都导致「没导入」，但
   处理方式不同：前者要换个格式或换个工具，后者要修文件。混成一句话「导入失败」
   会让调用方无从下手。
4. **重新导入材料不该抹掉标注。** 最初的实现每次导入都用请求里的关联覆盖现有的，
   于是「重导一遍更新教材」会**静默清空**教师之前标的知识点关联。三种语义
   （不改 / 清空 / 设置）把这件事说清楚了。
5. **材料只有一份，但两边各记一次。** 课程侧记「属于哪门课、覆盖哪些知识点」，
   RAG 侧记「切成什么样、嵌成什么向量」。强行合成一个类型会让两边都别扭——但
   代价是正文存两遍。
