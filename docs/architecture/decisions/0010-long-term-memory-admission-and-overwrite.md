# ADR-0010: 长期记忆的准入与覆盖语义

- 状态：已接受
- 日期：2026-11-23

## 背景

Topic 08 做了上下文管理，Topic 09 做了会话持久化。但会话记忆只在**一个会话内**
有效——学习者今天说的「我讨厌背公式」，明天开新会话时教练完全不知道。

长期记忆要跨会话保留**关于学习者的持久事实**：目标、水平、强项、弱点、偏好、
学习节奏。

Topic 10 提出的工程问题是：**什么信息值得进入长期记忆？如何避免把噪声写进
Memory Extraction？**

参考实现 `ai-agent-from-scratch` 的 Ch6 快照给出了基本形态：`TaskMemory`
（Pydantic schema）+ LLM 结构化输出抽取 + LLM 判重 + ChromaDB 向量存储 +
向量检索。

但它面向的是 **GAIA 解题记录**——「这道题怎么解的、对不对」，是**关于任务**
的记忆。本项目要的是**关于学习者**的记忆。这两者的结构、检索方式与噪声形态都
不一样，不能照搬。

更要紧的是：参考实现对「噪声」几乎没有防护。抽取出来就写进向量库，判重失败
时还**静默放行**（`_is_duplicate` 捕获所有异常返回 `False`）。噪声会长成
向量库里的一堆互相矛盾、无人能解释的碎片。

## 决策

**长期记忆按「(主体, 类型, 类别, 作用域)」唯一键 upsert；准入是确定性的；
召回在结构化筛选与关键词相关度之间，不引入向量检索。**

### 1. 三条准入条件

一条信息要进长期记忆，必须同时满足：

1. **归属**——是关于**谁**的？关于学习者的事实进长期记忆；工具输出、模型
   推测、一次性任务进展不进。
2. **耐久**——下次会话还成立吗？会随时间变化的状态（「今天学了闭包」）不进；
   稳定的事实与偏好才进。
3. **可覆盖**——它属于哪一类事实？同一类事实**只保留最新的一条**。

第 3 条是抑制矛盾记忆的关键。「水平从初级变成中级」如果表现为「多了一条记忆」，
画像里就会同时出现两个互相矛盾的水平。

### 2. 唯一键 upsert：覆盖而非并存

记忆的唯一键是 `(主体, 类型, 类别, 作用域)`。写入时按键 upsert：已有同键的
记忆被**取代**——保留原 id 与创建时刻，更新内容与更新时刻。

于是「水平变了」表现为「一条记忆被更新」，而不是「多了一条矛盾的记忆」。

`作用域` 用来区分「同一类别里不同的那一条」：留空表示该类别**只有一条**
（水平是单例），填具体值表示该类别下可以有多条（弱点按知识点区分）。

### 3. 准入是确定性的，模型说了不算

抽取出来的东西不等于该写进长期记忆。`MemoryPolicy` 在写入前做一次**确定性**
检查：内容非空、置信度达标、长度不超标、类别在词表内。

确定性很重要：**交给模型判断「这条算不算噪声」就等于没有判断**——同一个模型
两次判断可能不同，判断本身就成了噪声源。

类别词表（`LEARNER_MEMORY_KINDS`）是策略的一部分：不在词表里的候选被拒绝，
防止模型随手发明类别把记忆搅乱。词表是本项目当前的默认，Phase 1 的学习领域层
会扩展它。

### 4. 「没有值得记的东西」是合法且被期望的答案

抽取提示词明确要求「没有就返回空的 memories 列表——空列表是完全正确的答案，
不要为了凑数而编造」。

这条很重要。如果「没东西可记」不是一个被期望的答案，模型总会给你点什么——
**抽取的噪声主要来自这里，而不是来自模型的错误**。

### 5. 抽取失败明确抛出，不静默吞掉

参考实现的 `_extract_memory` 捕获所有异常返回 `None`（还打印到 stdout）。
本项目让 `LLMError` / `LLMParseError` **向上抛出**：抽取失败是需要被看见的
事实，调用方据此决定这一轮的记忆是丢了还是要重试。

「记忆写入不在热路径」这个原则（LangGraph 文档的 hot path vs background）
意味着调用方通常在后台任务里调用 `capture`，失败时记日志而不是冒泡。

### 6. 召回是结构化筛选 + 关键词相关度，不用向量检索

学习者的长期记忆是**结构化**的：几十到几百条事实，每条带类别与主体。绝大多数
召回是「给我这个学习者的弱点」——那是**筛选**，不是相似度检索。

剩下的「和当前话题相关的记忆」才是自由文本检索。对这种规模的小语料，
确定性的关键词匹配有三重好处：

- **不需要嵌入服务**。参考实现因此绑定了 OpenAI 的 embedding API，与本项目
  厂商无关的立场冲突。
- **完全离线可测**，结果确定。
- **结果可解释**——能说清为什么这条被召回。

向量检索留给 Day 11～12 的 RAG——那时嵌入与向量索引的基础设施会建起来，长期
记忆可以接上去。`MemoryStore` 是协议，接上向量实现不影响调用方。

中文分词用**二元组**（「闭包」切成「闭」「包」）：中文没有词边界，按空格切会
得到整句话；按二元组既能命中子串，又不至于把单字当成噪声。

### 7. 类型沿用 CoALA / LangGraph 的三分法

不自创分类：

- `semantic`：**事实**（关于学习者的事实）。
- `episodic`：**经历**（发生过的事）。
- `procedural`：**规则**（怎么教这个人）。

领域内的细分（目标 / 水平 / 弱点……）放在 `kind` 里，与 `memory_type` 分开——
这样记忆机制本身是领域无关的，Phase 1 换一套类别词表不影响机制。

### 8. 记忆要落盘，也要真的进到模型上下文

两件事容易被混为一谈：

- **持久化**（`JsonFileMemoryStore`）：记忆跨会话存活。一个主体一个 JSON 文件，
  写入先写临时文件再改名——**改名是原子的**。
- **上下文集成**（`MemoryManager.build_context`）：记忆真的进到模型请求里。
  不带查询时给学习者画像，带查询时给相关记忆；**没有内容时返回空字符串**，
  不给模型塞空话。

集成路径由应用层编排——运行时保持领域无关：

```python
context = await manager.build_context(subject=learner_id)
runtime = AgentRuntime(
    client,
    dispatcher,
    config=AgentConfig(model="gpt-4", instructions=[*base, context]),
)
```

### 9. 记忆写入不在 Agent 的热路径上

`MemoryManager` 只提供能力，**不决定何时调用**。由应用层决定什么时候抽取
（会话结束时？每 N 轮？用户主动触发？）。

LangGraph 文档指出在热路径里写记忆会增加延迟、让 Agent 分心、影响主任务质量。
本项目同样把这件事交给应用层。

## 后果

- 好处：矛盾记忆不会产生；噪声有三道闸（抽取提示词、准入策略、去重与覆盖）；
  召回不需要嵌入服务，完全离线可测且可解释；机制与领域分离。
- 代价：抽取依赖模型质量；准入策略是硬规则，误杀要靠调词表与阈值；
  关键词相关度比向量检索粗。
- 边界：**没有遗忘**。记忆只增不删，只有被同键的新记忆取代。学者的水平
  变了，旧的「初级」被覆盖；但「曾经是初级」这类历史信息无处安放。
- 边界：**没有冲突消解的语义层**。同键覆盖是「新的赢」；如果两条事实并不真正
  互斥（例如两个不同的学习目标却用了同一个作用域），覆盖会丢掉一条。
- 边界：**没有跨事实的关联**。记忆之间没有引用关系，因此「这个弱点是由哪个
  目标造成的」这类问题答不了。
- 边界：**没有时效性**。记忆不衰减；三个月前的偏好和今天的偏好权重相同。
- 边界：**没有并发写保护**。两个进程同时抽取可能互相覆盖。

## 补充说明（2026-11-23）

实现中确认的事实：

1. **「类型不认识的候选」不该让整批抽取失败**。模型给出一个不认识的
   `memory_type` 时，如果 schema 用枚举，pydantic 校验会让**整批**抛
   `LLMParseError`——一条坏数据毁掉整轮抽取。改成宽松的字符串 + 映射回退，
   坏的那条降级，其余照常。
2. **召回噪声和写入噪声一样有害**。写进去一条无关记忆，会在每次召回时都被
   注入上下文，占位置还干扰推理。因此「没有匹配就不返回」是一条硬要求，
   不是优化。
3. **重复 id 会留下陈旧的键映射**。存储同时维护「id → 记忆」和「键 → id」
   两张表；id 复用但键不同时，旧键映射会指向一条已经被换掉的记忆，按键查找
   会捞出错误的内容。**索引整体重建**而不是增量维护——增量维护要小心翼翼地
   记得清理，而重建从根上不可能不一致。代价是 O(n)，而这里的 n 是几十到几百。
