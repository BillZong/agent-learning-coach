# ADR-0036: 苏格拉底式教学——引导的三阶段与模式切换

- 状态：已接受
- 日期：2026-11-27

## 背景

Day 34（Phase 2 · AI Tutor）的工程问题是：**苏格拉底式怎么实现？提问、追问、
回答理解、教学模式切换怎么做？两种模式的效果怎么对比？**

Day 33 已经把「教学模式只决定指令」这条设计定下来了（ADR-0035 ✓）——所以本主题
要解决的是**指令之外的部分**：提问的结构、听完之后的判断、以及什么时候该换模式。

## 研究

### GuideEval 的三阶段框架

Liu et al.（Findings of EMNLP 2026）把「教学引导」（instructional guidance）拆成
三个阶段，并用真实教学对话构造了基准 GuideEval：

| 阶段 | 问什么 |
| ---- | ------ |
| **Assessment** | 学习者现在是什么状态？ |
| **Orchestration** | 下一步该换哪种策略？ |
| **Elicitation** | 怎么问才能引出真正的反思？ |

**这篇论文最关键的实测结论**：**现有 LLM 在学习者困惑或需要引导时，常常给不出有效
的适应性支架**——它们是「通用教练」而不是「善解人意的教练」 ✓✓。

**这直接改写了对「苏格拉底式」的理解**：**用苏格拉底式的语气问问题 ≠ 在引导** ✓。
引导的核心是**根据学习者的状态调整策略** ✓——而那正是现有模型最弱的地方。

### 教学研究里的相关结论

- **worked example 与直接教学**（Day 33）：示范先给、练习后跟；苏格拉底式是**另一
  条路**——它不给示范，而是让学习者自己走到结论 ✓；
- **渐隐支持**（Renkl & Atkinson）：支持要随熟练度递减——这正好是「模式切换」的
  另一个理由 ✓✓（学会了就该讲得更少，答错太多次就该直接讲 ✓）。

## 决策

### 1. 三阶段各自落地，不混在一个提示里

| 阶段 | 实现 |
| ---- | ---- |
| Assessment | `SocraticAssessment.understanding`：**困惑 / 部分对 / 答对** ✓ |
| Orchestration | `SocraticAssessment.next_step`：**追问 / 提示 / 揭示 / 下一个** ✓ |
| Elicitation | `SocraticQuestion`：问题 + 提示方向 + 引用 ✓ |

**为什么分两次调用**（提问一次、判断一次）：**判断需要学习者的回答**——没有回答就
没有状态可判断 ✓。合成一个「问 + 判」的调用会让模型在没有回答时也去判 ✓。

### 2. 模式切换是**业务判断**，由策略给

`choose_next_mode(assessment)`：

- **reveal → 切回直接教学** ✓——继续追问没有意义时还问，是在消耗学习者的耐心 ✓；
- 其余情况留在苏格拉底式 ✓；
- **学习者明确要求「直接告诉我」→ 直接讲** ✓✓——**苏格拉底式是手段不是目的** ✓。

### 3. 提问必须带**提示方向**

`SocraticQuestion.hint` 是必填的字段（不是可选的补充）✓——**没有提示，学习者卡住
就只能干等** ✓。

**苏格拉底式不给答案，但必须给出路** ✓。

### 4. 两种模式的对比：**只比共同的部分**

共同的部分是**引用与门禁**（两种模式都过 Day 31 的门禁 ✓）——引用声明率、编造率、
过门禁率 ✓。

**差异部分（讲解 vs 提问）不可比**——它们回答的是不同的问题 ✓✓。

**效果的对比要真实学习者** ✓：脚本化模型只能证明「管道通不通」✓——这一点写在
`ModeComparison.summary()` 里 ✓（不写在文档角落，而是**每次输出都带着这句话** ✓）。

## 后果

- 好处：**引导被拆成了可测的三段** ✓；模式切换有明确判据 ✓；提问必须带提示 ✓；
  两种模式的共同部分可以对比 ✓。
- 代价：**两次模型调用**（问一次、判一次）——延迟翻倍 ✓（评估阶段还只是文本，
  真实场景下这要算进体验 ✓）。
- 代价：**「判断」的质量完全取决于模型**——GuideEval 的实测说它常常做不好 ✓✓。
  本项目能做的只是**把判断的结构固定下来**（状态与下一步都是枚举 ✓），让错误可见
  ✓，而不是假装判断很准 ✓。
- 风险：**脚本化评估给不出质量结论**——判断准确率 0.12 是脚本化模型的必然结果 ✓，
  不是模型的真实水平 ✓。
- 边界：**真实效果对比待真实学习者** ✓；**苏格拉底式与练习的衔接**待 Phase 3 ✓；
  **多轮引导的策略**（连续追问几轮后揭示）只在指令里约束，没有机制 ✓。

## 补充说明（2026-11-27）

实现中确认的事实：

1. **「苏格拉底式的语气」是廉价的那一半**。GuideEval 的结论是模型在**引导**上很弱，
   而弱的那一半恰恰是**读懂学习者** ✓✓。所以本项目的重点放在 Assessment 与
   Orchestration，而不是把指令写得更有苏格拉底味 ✓。
2. **判断与提问要分两次调用**——判断需要学习者的回答 ✓（合成一次会让模型在没有
   回答时也去判 ✓）。
3. **模式切换的判据要写死**：reveal → direct ✓；学习者明确要求 → direct ✓。
   「苏格拉底式是手段不是目的」这句话落在了**代码**里（`choose_mode_for_request`），
   不是文档角落 ✓。
