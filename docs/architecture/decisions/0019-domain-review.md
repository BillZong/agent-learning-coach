# ADR-0019: 领域模型评审——Phase 1 收口的判断与补强

- 状态：已接受
- 日期：2026-11-25

## 背景

Topic 19 是 Phase 1 的评审主题，工程问题是：**当前领域模型是否已经能支撑 Phase 1
的用例？哪些不变量需要用 ADR 固化下来？**

Phase 1 到本主题为止已经建成四个聚合（ADR-0015、0016、0017、0018）：

| 聚合 | 回答 | ADR |
| ---- | ---- | --- |
| `Learner` | 学习者是谁 | 0015 |
| `Course` + `KnowledgeStructure` | 知识点及其依赖 | 0015、0016 |
| `LearningGoal` | 想达成什么 | 0017 |
| `LearningProgress` | 学到了哪 | 0018 |

Plan.md 的 Day 19 评审清单是：Learner Model / Course Model / Knowledge Model /
Learning Goal / **Repository Boundary** / 补充 ADR / 补充集成测试。

本 ADR 是**评审的结论**，不是新的建模决策——除了第 2 节那一处补强。因此它记录
的是「评审发现了什么、决定了什么」，而不是「我们又设计了什么」。

评审方法是**逐条对照**：把 PRD 的 Stage 与验收标准、Plan.md 的评审清单、
ADR-0015 留下的工程债，逐项拿到代码里验证，而不是凭印象写总结。

## 决策

**四个聚合的边界与 Phase 1 的用例匹配，不变量已由 ADR-0015～0018 覆盖；
本轮评审补上一处跨聚合校验缺口（学习者一致性），并把「持久化边界」从
ADR-0015 的搁置状态正式推进为「已决定但未实现」。**

### 1. Phase 1 用例的支撑情况

PRD 的六个阶段（Diagnose / Plan / Learn / Practice / Evaluate / Adapt）里，
**领域层目前直接支撑的是 Stage 1 与 Stage 2 的建模部分**：

| PRD 阶段 | 领域层提供 | 缺什么 |
| -------- | ---------- | ------ |
| Stage 1 Diagnose | `Learner`（画像）、`KnowledgeStructure`（依赖）、`LearningProgress`（已有知识） | **诊断策略**：谁被判定已有基础（Topic 20）、怎么找缺口（Topic 20 / 43） |
| Stage 2 Plan | `LearningGoal`（意图 + 约束 + 绑定）、`to_goal_spec`（交接） | 计划任务与知识点的粒度对齐（Topic 23） |
| Stage 3～6 | —— | 学习会话、练习、评估、适配（Phase 2～4） |

roadmap 的 Phase 1 验收标准逐条对照：

| 验收标准 | 状态 | 说明 |
| -------- | ---- | ---- |
| 能够创建和管理学习领域 | **部分** | 领域模型齐了；**没有持久化**，「管理」目前只在内存里成立 |
| 能够组织知识点及其依赖关系 | **是** | `KnowledgeStructure` + ADR-0016 的闭包查询 |
| 能够创建学习目标 | **是** | `LearningGoal` + 六状态状态机（ADR-0017） |
| 能够根据学习者背景开展初始诊断 | **否** | 策略缺失（Topic 20） |
| 能够识别初步知识缺口 | **否** | 判定阈值缺失（Topic 45） |
| 能够生成结构化、可执行的学习计划 | **是** | `OutcomePlanner` + `to_goal_spec`（ADR-0013） |
| 学习计划能够持久化并被后续模块使用 | **是** | 会话快照（ADR-0009） |

结论：**领域模型本身不是 Phase 1 的瓶颈**。剩下的三条未达标项全部落在
「策略层」（诊断、缺口判定）与「持久化」，不是模型形状的问题。因此**不为
Phase 1 收口再改模型形状**——这正是本主题应该得出的结论：继续建模的边际
收益低于补策略。

### 2. 评审发现的一处真实缺口：跨学习者的完成度

`goal_completion(progress, goal)` 原本只校验**课程**一致，不校验**学习者**
一致。评审用一段代码验证了这个缺口：

```python
progress = LearningProgress(learner_id=LearnerId("learner-2"), course_id=CourseId("c1"))
goal = LearningGoal(id=GoalId("g1"), learner_id=LearnerId("learner-1"), course_id=CourseId("c1"), ...)
goal_completion(progress, goal)   # 不报错，算出了 learner-1 的目标完成度
```

**A 的进度算出了 B 的目标完成度。** 这不是理论问题：进度是按（学习者 × 课程）
分片的（ADR-0018），一个课程下会有多个学习者的进度；把它们混在一起算，
结果是错的而且**看起来是对的**。

修正：`goal_completion` 现在同时校验学习者与课程，不一致就抛 `DomainError`。

这条缺口的成因值得记下：**ADR-0018 把「进度按课程分片」定下来时，没有回头检查
「进度与目标如何配对」**。分片的键是 `(learner_id, course_id)`，而配对的键应该是
**同一个**——评审补上了这一环。

### 3. 不变量清单：哪些已被 ADR 固化

评审把四个聚合的不变量逐条列出，确认**每一条都有出处**，不需要新 ADR：

| 不变量 | 固化在哪 |
| ------ | -------- |
| 知识点 id 唯一、关系端点存在且不重复、`requires` 无环、`part_of` 一子一父 | ADR-0016 |
| 关系外置在结构里，知识点不持有前置 | ADR-0016 |
| 顺序与闭包是派生视图，不持久化 | ADR-0016 |
| 实体不可变，身份来自 id | ADR-0015 |
| 跨聚合只按 id 引用，双向引用必须双写 | ADR-0015 |
| 目标状态由迁移历史派生，终态不可回退 | ADR-0017 |
| 约束是结构化值对象，能力要求指向已有结果 | ADR-0017 |
| 保证责任三档（聚合内 / 跨聚合 / 外部事实） | ADR-0017 |
| 进度按（学习者 × 课程）分片，绑知识点不绑任务 | ADR-0018 |
| 学习状态与任务状态分离，被阻塞是派生结果 | ADR-0018 |
| 已有知识是迁移序列的第一条 | ADR-0018 |
| 进度状态由迁移历史派生，每条边一个操作语义 | ADR-0018 |

**没有需要新 ADR 的不变量**——这是评审给出的正面结论：Phase 1 的建模决策已经
自洽且有据可查。

### 4. 持久化边界：从「搁置」推进到「已决定」

ADR-0015 §7 写着「**不做 Repository / ORM**。Phase 1 目前没有数据库选型
（架构文档里 TBD）」。这个前提**已经不成立了**：

- 架构文档的选型表已写明「关系型数据库：PostgreSQL（计划采用）」、
  「向量数据库：PostgreSQL + pgvector（已确定）」；
- `pyproject.toml` 已经引入 `psycopg[binary]` 与 `pgvector`；
- `core/rag/store.py` 里已有 pgvector 的生产实现与建表语句（ADR-0011）。

也就是说，**ADR-0015 搁置仓储层的理由（选型未定）已经消失，但 ADR 没有更新**。
评审的判断：

- **选型已定这件事本身需要一条 ADR 固化**——「学习领域用 PostgreSQL 持久化」
  是一个架构决策，不该只躺在架构文档的选型表里；
- **但本主题不实现仓储层**。理由：领域模型刚定型（ADR-0018 是昨天的事），
  现在造仓储会立刻遇到「不可变实体 + 迁移历史怎么存」的持久化形态问题，而那个
  问题在 Topic 18 的遗留项里已经记着（进度按知识点逐条更新，整体重建成本上升）。
  先有形态决策，再有仓储。

因此本 ADR 只**记录边界**：学习领域的持久化目标是 PostgreSQL（与向量库同库，
复用 ADR-0011 已有的连接与迁移设施）；仓储层的接口形态、迁移历史的存储方式、
写路径如何复用领域校验，留给后续主题。

**写路径必须复用领域校验**这条要特别记下——ADR-0015 遗留的最大工程债是
「不变量只在内存校验」：接数据库后会出现「内存里合法、库里非法」的两套规则。
这条约束在 ADR-0015 已写，本 ADR 再次确认它适用于四个聚合。

### 5. 补集成测试：四个聚合协同走一遍

Plan.md 的清单里有「补充集成测试」。评审发现：现有测试**全部是单聚合的**——
`test_learning_domain.py`（Learner/Course）、`test_knowledge_structure.py`
（知识结构）、`test_learning_goal.py`（目标）、`test_learning_progress.py`（进度）。
**没有任何一个测试让四个聚合一起动。**

这是真实缺口：单聚合测试全绿，但「诊断 → 目标 → 进度 → 完成度」这条链是否
接得上，没有测试证明。集成测试要覆盖：

1. 完整链路：画像 → 课程结构 → 目标（绑定知识点）→ 诊断判定已有基础 → 学习 →
   进度 → 目标完成度；
2. **跨聚合一致性检查在这条链上真的会被调用**（而不是各测各的）；
3. 三个终态路径（达成 / 放弃 / 过期）在有进度的情况下行为正确；
4. 跨聚合校验的**失败路径**也能走通（引用不存在的知识点、违反前置封闭性）。

集成测试放在 `tests/test_learning_workflow.py`：它验证的是**聚合之间的协作**，
不重复单聚合测试已覆盖的不变量。

### 6. 明确不做的事

评审同时确认了这些**不该在 Phase 1 做**的事，避免下次评审又讨论一遍：

| 不做 | 原因 |
| ---- | ---- |
| 为收口再改模型形状 | 验收标准的缺口全在策略层与持久化，不在模型 |
| 引入仓储层 | 持久化形态（不可变实体 + 迁移历史怎么存）尚未决策 |
| 实现诊断策略 | 属于 Topic 20 |
| 实现薄弱点判定 | 属于 Topic 45 |
| 掌握度量化 | 属于 Topic 43 |
| 复习调度 | 属于 Topic 52 |
| 全局知识地图 | 属于 Topic 22 |

## 后果

- 好处：Phase 1 的建模阶段**可以收口**——四个聚合的形状经过 15～18 四个主题
  逐个加固，评审确认它们能支撑 PRD Stage 1～2 的建模部分，且每条不变量都有 ADR
  出处；`goal_completion` 的跨学习者缺口被补上；集成测试首次让四个聚合一起动。
- 代价：**「能够创建和管理学习领域」仍未完全达标**——缺持久化。这是 Phase 1
  剩余的最大工程债，评审不掩饰它。
- 代价：持久化目标写进 ADR 但**没有实现**，评审的结论是「该做但不急」——这个
  取舍需要有人认领，否则会一直搁置。
- 风险：**集成测试可能固化错误的协作方式**。若四个聚合的协作约定本身有问题，
  集成测试会把错误固化成「期望行为」。评审的缓解是：集成测试只断言**跨聚合的
  契约**（一致性检查被调用、完成度算对、终态行为正确），不绑定实现细节。
- 边界：诊断、缺口判定、掌握度、复习调度、持久化形态、跨课程身份都仍未建模。

## 补充说明（2026-11-25）

评审中确认的事实：

1. **评审要拿代码验证，不能凭印象。** 「跨学习者完成度」这条缺口，是评审写
   了一段验证代码才暴露的；单看 ADR-0018 的文字描述（进度按学习者 × 课程
   分片）看不出问题——**文档自洽不等于实现正确**。
2. **派生查询是校验缺口的高发区**。`goal_completion` 漏了学习者一致性，是因为
   它是在 Topic 18 写完主体模型后补的「顺手查询」，没有回头检查它接受的参数
   是否配对。派生查询的入参配对规则应当与构造期校验同等对待。
3. **ADR 会因为前提消失而失效**。ADR-0015 的「不做仓储层」依赖「选型 TBD」，
   选型定了之后这条理由就不成立了，但 ADR 不会自己更新。**评审必须回头读早期
   ADR 的前提是否还成立**——这正是 Plan.md 清单里「Review Repository
   Boundary」的用意。
4. **单聚合测试全绿不等于模型能协同**。四个聚合各自测试充分，但它们之间的
   协作（一致性检查是否真被调用、完成度是否算对）没有任何测试覆盖。
5. **「验收标准未达标」要区分模型问题与策略问题**。Phase 1 剩三条未达标，其中
   两条（诊断、缺口）是策略问题，一条（持久化）是基础设施问题——**没有一条是
   模型形状问题**。这个区分决定了本主题该做什么（补测试、补 ADR）而不是改模型。
