# Topic: Structured Generation

> Day 21 ｜ Phase 1 · Learning Core ｜ 主教材：—（本阶段无主教材章节） ｜ 外部参考：JSON Schema 与结构化输出（OpenAI / Anthropic 文档）、Self-Refine（Yang et al.）、LLM-as-a-Judge（Zheng et al.） ｜ 状态：已完成

## 1. Engineering Question

生成的诊断题如何做结构化校验？无效题目应该在生成层拦截，还是在评估层兜底？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **结构化输出要两层校验。** JSON Schema 那一层管「模型有没有按格式回答」；
    业务规则那一层管「这个回答在业务上成不成立」。两层混在一起，格式错误就会
    带着业务语义跑，业务规则也会被迫理解模型的输出格式。
  - **无效输出要在能修的地方修。** 生成层可以要求模型重来；到了评估层，题目
    已经呈现给学习者，只能事后解释。**问题在能修的地方修**。
  - **反馈要具体。** 「失败了」对模型没有信息量；「难度与要求不符」才有。模型
    能看见自己错在哪，重试才是修复而不是碰运气。
  - **错误要分摘要与细节两档。** 摘要是给模型看的视图，原始条目是给排查问题的人
    看的事实。**摘要是视图，不是替代品**（ADR-0022）。
  - **重试与兜底要分层。** 题目不合格换一次输出可能就对了；调用超时重试只会
    把一次限流放大成 N 次。**传输问题与内容问题不是一回事**。
  - **不信任下游的前提是不把坏数据交出去。** 一旦交出去，下游就没有理由再怀疑
    它，判定会把它当成依据。

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  结构化输出要 schema 约束；输出要校验；校验失败要能重试；反馈要具体。
- **哪些观点存在分歧？**
  - **「语义正确的题目该由谁保证」。** 结构化输出的实践通常止步于 schema 通过；
    本项目要求题目还要在**业务上**成立（难度符合要求、针对目标知识点）。分歧
    来自**目标**：本项目的题目直接决定「学习者会不会」的判定，坏题的代价是
    判定失真，不只是体验差。
  - **「无效输出该重试还是该丢弃」。** 通用实践倾向于丢弃并降级；本主题选择
    重试，因为**生成层是唯一能修的地方**。分歧来自本项目把「诊断」当作核心
    功能而非可选增强。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**设计目标**：题目的下游是判定，不是展示。展示场景下丢弃坏题完全
  可以，判定场景下不行。
- **哪些结论缺少充分证据？**
  - **题面长度下限（8 字符）是启发式的。** 它挡得住「闭包？」，挡不住
    「解释一下闭包」这种同样没信息量的问法。没有数据支持这个阈值。
  - **「题面出现知识点实词」作为跑题判据。** 弱检查，挡得住完全跑题，挡不住
    角度偏了。没有实验验证它的漏检率。
  - **重试能提高多少合格率。** 机制上重试带反馈比不重试强（本项目的用例证明
    了「反馈确实被回喂」），但**没有测过**重试后的实际合格率提升。
- **哪些观点不适用于当前项目？**
  - **LLM-as-a-Judge 打分**：需要独立评估集与人工标注对齐，Phase 1 没有。
  - **多候选并行生成 + 择优**：需要题目质量的可比较评分，同样是 Topic 46 的事。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/learning/generation.py`**（新增）：
    - `ExerciseSchema`（pydantic）：**结构层**契约——字段齐全、类型正确、题面
      ≥ 8 字符、参考答案与理由 ≥ 4 字符、难度取值合法。
    - `ExerciseRequest`（值对象）：要考哪个知识点、要什么难度；**刻意不含学习
      者信息**（定制题属 Topic 22）。
    - `ExerciseGenerator`：**生成适配器**——调用模型 → 结构层校验 → 领域层校验
      → 失败带反馈重试。
    - `ExerciseGenerationError`：重试耗尽（或调用失败）时抛出；带 `message`
      （摘要）与 `detail`（原始细节）两档。
    - `_addresses_point`：**弱**跑题检查（题面/理由是否出现知识点实词）。
  - **`core/llm/errors.py`** + **`core/llm/structured.py`**：`FieldError` 与
    `LLMParseError.field_errors`——**原始错误条目在抛出点就被保留**，摘要
    （`.summary`）与细节（`.detail`）是它的两种视图（ADR-0022）。
  - **`core/learning/diagnosis.py`**：`DiagnosticExercise` 补齐 `expected_answer`、
    `difficulty`、`rationale`；难度取值放在领域模型里。
  - **`tests/test_learning_generation.py`**（新增）：15 个用例。
  - **`tests/data/exercise_cases.json`**（新增）：题目测试集，7 条用例覆盖两层
    拦截。
  - **`tests/test_exercise_dataset.py`**（新增）：8 个用例，按数据集驱动。
  - **`examples/exercise_generation.py`**（新增）：五段演示。
- **为什么这样设计？**
  - **在生成层拦截**：坏题会污染判定；生成层是唯一能重试修好的地方；评估层仍要
    校验，但那是防御性兜底不是主防线（ADR-0012「校验不能被绕过」）。
  - **两层不合并**：结构层可被其他生成场景复用；领域层只属于学习领域。
  - **题目不合格重试、调用失败不重试**：重试不会让超时变好，只会把一次限流放大
    成 N 次。
  - **反馈要具体**：失败原因压成一句人话再回喂，模型才知道自己错在哪。
  - **不合格题目不外流**：`generate()` 只有两种结局——返回合格题目或抛错。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 只做 schema 校验 | 格式对但业务错的题照样流出去，判定失真 |
  | 只在评估层兜底 | 题目已呈现给学习者，只能事后解释；坏题已污染判定 |
  | 无效输出直接丢弃 | 诊断覆盖率下降，缺口变成「未判定」，计划无从下手 |
  | 重试但不回喂原因 | 模型只能碰运气；「失败了」没有信息量 |
  | 调用失败也重试 | 一次限流被放大成 N 次，额度耗光 |
  | 题目与知识点关联用模型判定 | 需要可比较的评分（Topic 46），当前无评估基础 |
  | 把判官结果直接当判定 | 「用不确定验证不确定」，ADR-0014 明确避免 |
  | 生成器直接写进度 | 跨聚合写，破坏「一次事务只改一个聚合」 |
- **测试结果如何？**
  - `tests/test_learning_generation.py`：15 个用例（结构层拒绝：非法 JSON、缺字段、
    题面太短、难度取值非法；领域层拒绝：难度不符、题目跑题；重试：带反馈、
    耗尽抛错、坏题不外流；边界：调用失败不重试、生成器不认识诊断流程、领域模型
    拒绝非法难度）。
  - `tests/test_exercise_dataset.py`：8 个用例（7 条数据集用例 + 一条「数据集必须
    同时覆盖两层」）。
  - 全量：**724 passed**；`ruff` / `mypy` 全绿；八个示例跑通。
  - `examples/exercise_generation.py`：结构层拒绝显示
    `输出不符合要求的结构：expected_answer：Field required`；领域层拒绝显示
    `题目没有针对知识点「闭包」` 与 `题目难度为高级，与要求的进阶不符`；重试演示
    第一次失败原因被回喂；调用失败只调 1 次。
- **实践结果是否支持阅读材料中的观点？**
  支持两条：**两层校验**确实需要（只做 schema 时跑题题照样通过）；**带反馈重试**
  确实把信息给了模型（用例证明反馈进了下一次请求）。**不支持**「弱检查够用」——
  实词匹配挡得住完全跑题，挡不住角度偏了，这在本主题里就写明了。

## 6. Reflection

1. **今天最重要的知识是什么？**
   **「在哪一层拦截」是个可以论证的问题，不是品味问题。** 判据是「这层能做什么」：
   生成层能**重试**，评估层只能**解释**。所以拦截点应该在能修的地方。同一条判据
   也解释了另一件事：调用失败不该重试——那一层修不了它。
2. **哪个观点改变或修正了原来的理解？**
   原以为「结构化输出」= 「让模型按 schema 回答」，做完这一层就算完了。实际
   schema 通过只说明**模型听话了**，不说明**题目能用**。两道题的失败模式完全不
   同：格式错是模型没听话，业务错是模型听懂了但答偏了。
3. **当前实现还有哪些局限？**
   跑题检查是弱检查（实词匹配），漏检率未知；题面长度下限是启发式的；重试的
   实际合格率没测过；题目没有持久化（ADR-0019 决定仓储层后置）；没有多候选择优
   （需要评分基础）；生成的题目没人审阅——`rationale` 记下来了，但没人读。
