# Topic: Diagnostic Assessment

> Day 20 ｜ Phase 1 · Learning Core ｜ 主教材：—（本阶段无主教材章节） ｜ 外部参考：Formative Assessment（Black & Wiliam）、Knowledge Space Theory（Doignon & Falmagne）、Mastery Learning（Bloom, 1968） ｜ 状态：已完成

## 1. Engineering Question

诊断流程的输入、输出与准入条件是什么？诊断结果需要达到何种精度，才足以驱动学习计划生成？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **诊断是「形成性评估」，不是「终结性考试」。** 它的产出不是分数，而是
    **下一步该学什么**的判断——因此它的输出必须能直接接进计划生成。
  - **「不会」与「没测过」必须分开。** 二态评估里「不会」要同时表示两件不同的
    事，混起来会让教学重复已经会的内容。诊断的判定空间必须覆盖「不知道」。
  - **断言必须带依据。** 「学习者会闭包」这个判断，如果追不回依据（哪道题、
    什么作答、自述还是测评），那么计划跳过这个知识点就永远无法解释。
  - **诊断是一次活动，不是状态。** 同一个目标可以诊断多次（初诊、复诊）；每次
    都是一条独立记录，而不是覆盖上一条。
  - **「会」不等于「掌握」。** 诊断给的是离散判定；掌握程度是连续量，需要更多
    数据才能估计。

## 3. Cross References

| 来源 | 核心观点 | 与主教材的关系 |

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  诊断的产出要能驱动下一步；判定以知识为单位；判定要有依据；诊断是阶段性的
  活动而非一次性考试。
- **哪些观点存在分歧？**
  - **诊断要覆盖多少知识点。** ITS 实践通常只覆盖入口知识点（够确定知识状态即可），
    而本项目选择「目标要求的每个知识点都有判定」才准入。前者成本低、后者保守。
    分歧来自**应用场景**：ITS 的目标是尽量少提问尽快开始学，本项目的目标是为
    「个人化路径」提供可靠起点。
  - **判定的粒度。** ITS 常给出连续掌握度概率；本项目只给离散的三态。分歧来自
    **数据条件**：概率化需要题库与学习历史，Phase 1 两样都没有。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**数据条件与应用场景**：覆盖度与精度都是「够用即可」的问题，而「够用」
  的标准随数据量变化。
- **哪些结论缺少充分证据？**
  - **「覆盖完整才准入」可能过严**。目标要求 20 个知识点时，逐个判定才能准入；
    若诊断成本高，实际流程可能需要折中。这条规则没有实验依据。
  - **三态够不够。** 「测了不会」也可能程度不同（完全不会 vs 勉强通过）。三态把
    这些差异压平了，压平是否可接受没有数据支撑。
  - **判定质量完全取决于题目质量**。领域层能保证「有依据」，保证不了「依据有效」。
- **哪些观点不适用于当前项目？**
  - **概率知识空间（PKS）与掌握度分布**：需要大规模题目数据与学习历史。
  - **诊断的实时自适应出题**：那是 Topic 21 的题目生成策略。
  - **诊断结果的知识点映射与降级**：题目与知识点的对应、映射缺失时怎么办，是
    Topic 22 的题目。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/learning/diagnosis.py`**（新增）：
    - `Diagnosis`（实体）：`id`、`learner_id`、`goal_id`、`verdicts`；一次诊断
      **活动**，有独立 `DiagnosisId`（可多次诊断）。
    - `DiagnosticVerdict`（值对象）：`point_id`、`verdict`、`reason`、`basis`、
      `basis_kind`。
    - `Verdict = known | gap | unknown`——**三态**。
    - `DiagnosticExercise` / `DiagnosticSubmission`（值对象）：诊断题与作答的形状。
    - 判定查询：`verdict_for()`、`known_points()`、`gap_points()`、
      `undetermined_points()`。
    - **准入条件**：`has_full_coverage(goal)`、`missing_points(goal)`。
    - 跨聚合查询 `diagnosis_plan(diagnosis, goal)`：准入结论 + `teachable`（要教
      的内容）+ `undecided`（不知道的内容）+ `coverage_ratio`。
  - **`core/learning/domain.py`**：新增第五类标识 `DiagnosisId`。
  - **`tests/test_learning_diagnosis.py`**（新增）：17 个用例。
  - **`examples/learning_diagnosis.py`**（新增）：判定 → 准入 → 分清 → 衔接。
  - **文档**：ADR-0020、ADR 索引、domain.md、架构 §3.3、roadmap Phase 1。
- **为什么这样设计？**
  - **三态而不是二态**：二态会让「测了不会」与「根本没测」共用一个值，计划因此
    把没测过的点当作不会，重复教已会的内容。
  - **依据必填**：没有依据的「会」不可审计——事后查不出为何跳过这个知识点。
  - **准入落在领域层**：「目标要求的点有没有都被判过」是**集合覆盖问题**，可以
    现在就实现并测试；「精度够不够」是经验问题，要实证。
  - **诊断不持有进度**：进度由 `LearningProgress` 持有；两份状态就是两份副本。
  - **衔接靠现有接口**：ADR-0018 的 `assess()` 已预留接口，本主题只提供判定侧；
    **不提供「诊断自动同步进度」**——那是跨聚合写。
  - **题目生成不归本模块**：Topic 21 的事；这里只定义题目作为输入的形状。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 判定用二态（会 / 不会） | 「没测过」混进「不会」，计划重复教已会的内容 |
  | 判定不带依据 | 「会」不可审计；计划跳过某点时说不清为什么 |
  | 诊断直接改进度 | 跨聚合写，破坏「一次事务只改一个聚合」 |
  | 诊断挂在目标上（目标的一部分） | 目标要同时承载意图与活动记录，两类生命周期混在一起 |
  | 诊断按（学习者, 目标）分片 | 复诊会覆盖初诊；每次诊断应是独立记录 |
  | 准入条件交给应用层判断 | 「覆盖完整」是可判定的规则，不该外包 |
  | 准入条件改成「部分覆盖即可」 | 需要先有「部分覆盖」的语义与代价说明，目前没有 |
  | 判定带连续掌握度 | 需要题库与学习历史；Phase 1 没有 |
- **测试结果如何？**
  - `tests/test_learning_diagnosis.py`：17 个用例（依据必填的三种拒绝、理由非空、
    三态查询、覆盖完整与未覆盖、准入结论、teachable 与 undecided 分开、配对
    拒绝、判定 → 进度的 `assessed` 迁移）。
  - 全量：**701 passed**；`ruff` / `mypy` 全绿；七个示例跑通。
  - `examples/learning_diagnosis.py`：无依据的判定被拒；只判 k1 时「够驱动计划
    生成吗 False、未覆盖 ['k2']」；覆盖完整时「要教 ['k2']、不知道 []、覆盖率
    100%」；判定 → 进度迁移来源 `assessed`。
- **实践结果是否支持阅读材料中的观点？**
  支持两条结构层结论：**三态是必要的**（二态确实无法表达「没测过」）；**准入要
  按「能否驱动计划」定**（覆盖完整这条规则可以被直接测试）。
  **不支持**「覆盖完整是合适的门槛」——这条规则没有实验依据，与 ITS 实践的
  「只测入口知识点」直接冲突。

## 6. Reflection

1. **今天最重要的知识是什么？**
   **「精度够不够」这个问题问错了。** 它听起来是经验问题，但其实可以拆成两个：
   **「有没有覆盖到」是集合问题**（目标要求的点有没有都被判过——可判定、可测试、
   属领域层），**「判得准不准」才是经验问题**（需题库与学习数据、属实证）。
   把可判定的部分从经验问题里拆出来，是本主题能交付规则的前提；否则就只能
   写一句「由应用层判断精度」。
2. **哪个观点改变或修正了原来的理解？**
   原以为「诊断」是一个**状态**——像进度那样挂在目标上、记「诊断过了」。实际上
   诊断是**活动**：初诊、复诊都要留痕，所以它需要独立身份与独立记录。这与
   ADR-0018 把进度按（学习者 × 课程）分片的判断是同一条线索——**状态与活动要
   分开建模**。
3. **当前实现还有哪些局限？**
   判定质量取决于题目质量，领域层保证不了；「覆盖完整」可能过严且没有折中口子；
   三态压平了程度差异；判定与进度之间需要应用层显式衔接；诊断题生成、结果映射、
   掌握度、薄弱点都未建模。
