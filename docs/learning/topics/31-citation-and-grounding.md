## 1. Engineering Question

引用如何保证生成内容可溯源？当引用与原文不符时，应该由哪一层拦截？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **attribution 与 citation 是两个维度**：前者问「内容能不能追溯到证据」（不要求
    显式引用），后者问「引用对不对、全不全」。
  - **主流的引用质量判定用 NLI 蕴含**，不是词面交集——词面支撑是蕴含的**必要不
    充分条件**。
  - **编造引用比没有引用更危险**：没有引用是「没有依据」，编造引用是「假装有依据」。
  - **没有引用不等于错**：讲通用概念时，模型用自己的知识回答是合理的。
  - **inline 标记 + 段落级证据是主流那一档**（60%+ / 40%）。

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  引用必须指向真实存在的来源；编造比缺失更严重；判定要分「引用」与「内容是否被支撑」
  两层；引用要可核验（指向具体位置）。
- **哪些观点存在分歧？**
  - **支撑怎么判定**。文献主流用 **NLI 蕴含**；本项目用**词面交集**。分歧来自
    **依赖与延迟**：蕴含要额外模型，词面是现成的。代价是**词面有假阴性**（实测
    漏报 1/12）。
  - **「没有引用」是错误还是警告**。严格派认为无引用即不可信；本项目按 ADR-0012 判
    为**警告**——讲通用概念时无引用是合理的。分歧来自**场景**（材料相关 vs 通用）。
  - **不支撑该拦还是该提示**。本项目按 ADR-0012 判为**警告**（不拦截）。分歧来自
    代价观：拦截能防错，代价是重试与延迟。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**场景**（教学 vs 事实问答）与**依赖预算**（有没有 NLI 模型）。
- **哪些结论缺少充分证据？**
  - **词面门槛该怎么定**——显然要提高重叠门槛，但**12 条用例定不出一个门槛**
    （Day 30 的纪律）。
  - **真实模型的引用质量**——本项目**一条真实答案都没有**（全是人工合成）。
  - **拦截的代价**——一次重试多一次模型调用，没量过延迟。
- **哪些观点不适用于当前项目？**
  - **NLI 蕴含判定**：要额外模型与依赖，且默认套件不能依赖外部服务。
  - **FActScore 式原子事实分解**：要模型拆句子，本项目做不了。
  - **LLM-as-a-judge 评估引用**：判官不可回归，不能当门禁（ADR-0014）。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/application/grounding.py`**（新增）：支撑门禁。
    - `GroundingPolicy`：`require_citation` / `block_on_fabrication` /
      `retry_instruction` / `fallback_text`（四道可配的旋钮）；
    - `GroundingResult`：三档判定（`grounded` / `ungrounded` / `fabricated`）+
      报告 + 引用 + 说明 + 重试指令 + 兜底话术；
    - `check_grounding` / `evaluate_answer` / `collect_citations`（从草稿本取回引用）。
  - **`core/rag/citation_evaluation.py`**（新增）：引用评估。
    - `CitationCase`（标注的是「校验器应该报什么」）、`CitationCaseResult`、
      `CitationMetrics`；
    - `evaluate_citations`：校验器准确率 / 精确率 / 召回率 + 引用精确率 / 覆盖率 /
      编造率 + 按类别分组；
    - `load_citation_cases`。
  - **`evals/citations.json`**（新增）：12 条用例，五类（supported / fabricated /
    unsupported / missing / mixed）。
  - **`examples/citation_evaluation.py`**（新增）：四段演示。
  - **测试**：`tests/test_citation_evaluation.py`（18）、`tests/test_grounding.py`（12）。
  - **文档**：ADR-0033、ADR 索引、`rag.md`、roadmap、Topic 31 笔记、Day 31 记录。
- **为什么这样设计？**
  - **门禁在应用层**：领域层不选边（ADR-0020）；`core.rag.citation` 只判定，
    应用层处置，策略由调用方给 ✓；
  - **拦截时不给原文**：那段文字里有编造的引用，递过去就是递假引用 ✓；
  - **拦截配重试路径**：严格门禁的失败模式是沉默 ✓；
  - **词面口径 + 上界估计**：没有 NLI 模型，但**必须说清这是上界**，不能当「引用有
    多准」对外说 ✓；
  - **评估集人工合成且必须明说**：它量的是机制，不是真实模型 ✓。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 门禁放在 `core/rag/citation` | 检索层就要知道业务策略 ✗——违反 ADR-0020 的分层 |
  | 拦截时给原文 + 提示 | 学习者照样看见编造的引用 ✗ |
  | 拦截但不配重试 | 学习者只看到沉默 ✗ |
  | 用 NLI 蕴含判定 | 要额外模型与依赖；默认套件不能依赖外部服务 ✗ |
  | 立刻提高词面门槛 | 12 条用例定不出门槛 ✗（Day 30 的纪律） |
  | 只报汇总数字 | 不知道漏的是哪一条 ✗ |
- **测试结果如何？**
  - `tests/test_citation_evaluation.py`：18 个用例（评估集加载、四类情形齐、坏评估集
    报错、编造/不支撑/无引用都能查出、精确率与召回率分开、引用精确率随错引用下降、
    编造率、覆盖率、按类别分组、摘要含六个指标）。
  - `tests/test_grounding.py`：12 个用例（三档判定、两道闸可配、不支撑是警告、
    草稿本取回引用、畸形条目跳过、答案与参考文献一起交付、**拦截时不给原文**）。
  - 实测指标（12 条用例）：校验器准确率 **0.92**、精确率 **1.00**、召回率 **0.83**；
    引用精确率 0.62、覆盖率 0.81、编造率 0.23。
  - 全量：**978 passed**（+30）；`ruff` / `mypy` 全绿；二十八个示例跑通。
- **实践结果是否支持阅读材料中的观点？**
  支持三条：**编造比没有引用更严重**（门禁默认拦截编造）；**attribution 与 citation
  是两层**（本项目只做 citation 那一侧，边界写进 ADR）；**引用质量必须量**（没有量
  就只能靠感觉调）。**修正**一条：以为「拦截 = 不给答案 + 一句提示」就够——
  实现时才发现**给原文等于递假引用**，必须连原文一起扣住 ✓。

## 6. Reflection

1. **今天最重要的知识是什么？**
   **attribution 与 citation 是两个维度，而本项目只做了后者的一半。** 文献用 NLI
   蕴含判断「说法是否被材料支撑」（attribution），用 gold standard 判断「引用是否
   指向对的来源、该引的是否都引了」（citation）。本项目的校验器做的是 citation 侧的
   **存在性**（编造 / 指错），**没有做 attribution**——「答案里的说法本身是不是材料
   支持的」没人查。**知道自己没做哪一半，比把做过的那一半说得好更重要。**
2. **哪个观点改变或修正了原来的理解？**
   原以为「拦截 = 不给答案 + 加个提示」。实现时才发现：加了提示却**仍然把原文递过去**
   ——学习者照样看见那个编造的引用。**拦截的语义是「不交付」，不是「打个折扣交付」**。
   另外：补救话术与重试指令是两件事——给学习者的是「我没找到依据」（诚实），给模型
   的是「只引用出现过的标记」（可执行）。
3. **当前实现还有哪些局限？**
   词面口径有**假阴性**（共享「返回」两个字就算支撑，实测漏报 1/12），而门槛定不出；
   评估集是人工合成的，**一条真实答案都没有**；**attribution 那一层没做**（说法本身
   是否被支撑没人查）；拦截的重试成本没量；引用精确率是**上界估计**，不能当「引用有
   多准」对外说。
