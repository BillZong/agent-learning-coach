## 1. Engineering Question

诊断结果如何映射到知识点？当题目与知识点的映射缺失时，系统应该如何降级？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **映射必须由题目声明，不能由评估推断。** 推断出的映射无法审计——「为什么
    判定这个知识点会」要有答案。
  - **映射缺失是信息不全，不是信息矛盾。** 前者要降级并报告，后者要报错。混为
    一谈，要么让矛盾悄悄通过，要么让正常情况不断报错。
  - **判断要能追溯到依据。** 「会」这个断言必须指向具体的题目与作答，否则无法
    审计，也无法在出问题时定位。
  - **「判不了」是一等状态。** 开放题没有唯一答案；算作答错会凭空制造知识缺口，
    算作答对会掩盖缺口。
  - **诊断的目的是找出要补的地方。** 汇总规则因此从严：宁可多教一点，也不
    跳过真正没学会的知识点——知识点之间有先修依赖，跳过一处会让后面全部塌掉。

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  判定要有依据；映射要显式；测不准不等于不会；诊断产出要能驱动下一步。
- **哪些观点存在分歧？**
  - **汇总该多严。** 形成性评估文献多强调「给出下一步建议」而非「打分精确」，
    因此宽松汇总（有一道对就算会）也有支持者。本项目选**严格汇总**，理由是
    先修依赖：漏教的代价（后续塌方）远大于多教的代价（浪费一点时间）。分歧
    来自**设计目标**——本项目把「知识依赖」看得比「评价观感」重。
  - **映射缺失该「猜」还是「留空」。** 工程实践里常见做法是用题目文本反查知识
    点。本项目拒绝推断：推断出的映射无法审计，而且猜错的映射会让判定建立在错误
    的地基上——那正是 ADR-0018 记录过的「坏题污染判定」的另一种形式。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**设计目标**：本项目要的是「可审计的诊断链」，不是「尽可能填满的诊断
  表」。填充率与可审计性在这里是对立的。
- **哪些结论缺少充分证据？**
  - **严格汇总会高估缺口**：一道题的偶然失误就判成不会。没有「一个知识点出几道
    题才算判准」的阈值依据（Topic 44）。
  - **精确匹配的可判定范围**：只对有唯一答案的题目有效。Phase 1 若主要出开放题，
    诊断覆盖率会很低。这个权衡没有数据支撑。
  - **降级报告对调用方是否够用**：补题、忽略、人工处理三条路线的成本未比较。
- **哪些观点不适用于当前项目？**
  - **概率化能力估计**：需要题目难度参数与学习历史，Phase 1 没有。
  - **判官偏差校正**（位置去偏、多判官投票）：Topic 39 才有意义。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/learning/assessment.py`**（新增）：
    - `Grader` 协议：判定一次作答对错——**领域层定义「需要判官给出什么」，不规定
      怎么判**。
    - `Grading` 三态：`correct` / `incorrect` / `undecided`（判不了）。
    - `ExactMatchGrader`：归一化后精确匹配；**无参考答案时判 `undecided`** 而不是
      答错。
    - `DiagnosticEvidence`：题目 + 作答 + 判定结论 + 归属知识点（可空）。
    - `assess_diagnosis(exercises, submissions, grader)` → `AssessmentResult`：
      判定、全部证据、降级报告。
    - `DegradationReport`：映射缺失与判不了**分开**报告。
  - **`core/learning/diagnosis.py` 的三处模型修正**（评审读代码发现的缺口）：
    - `DiagnosticExercise.point_id` **可空**——映射缺失从此可表达。
    - `DiagnosticSubmission` 去掉手填的 `correct`——作答只承载事实。
    - `DiagnosticVerdict.basis`（单条）→ `evidence`（多条），并**校验判定与证据
      一致**。
    - `Diagnosis` 增加 `evidence` 字段：保留全部证据，不只是支撑判定的。
  - **`core/text.py`**：新增 `normalize_for_match`；`core/agent/planning.py` 的
    `normalize_content` 改为委托——判重与比对答案共用一条规则。
  - **`tests/test_learning_assessment.py`**（新增）：18 个用例。
  - **`examples/learning_assessment.py`**（新增）：五段演示。
  - **迁移**：`examples/learning_diagnosis.py`、`tests/test_learning_diagnosis.py` 改用
    新 API。
- **为什么这样设计？**
  - **映射由题目声明，不由评估推断**：推断出的映射无法审计。
  - **映射缺失可表达**：外部题库、历史题、跨课程题确实不知道考点；靠约定藏起来会让
    降级无处落地。
  - **判定交给判官协议**：精确匹配是一种实现，LLM 判官是另一种（Topic 39）；换判官
    不改领域模型。
  - **汇总从严**：诊断的产出是「要补什么」；知识点有先修依赖，漏教比多教危险。
  - **降级不抛异常**：映射缺失是诊断的正常结果；矛盾才是失败。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 推断映射（用题目文本反查知识点） | 映射无法审计；猜错会让判定建立在错误地基上 |
  | 映射缺失就丢弃该题 | 诊断覆盖了什么不可回答；学习者答过的事实被抹掉 |
  | 映射缺失抛异常 | 外部题库一导入就报错，诊断无法进行 |
  | 宽松汇总（有一道对就算会） | 计划跳过真正没学会的知识点；先修依赖被破坏 |
  | 严格汇总（当前选择） | 高估缺口，多教一点 |
  | 汇总多数决 | 「几道题算几道」需要阈值，无依据 |
  | 作答自带 `correct` | 判断可被随手填成 True，依据无处安放 |
  | 判定只存单条依据 | 多题场景丢掉其余依据 |
  | 不校验判定与依据一致 | 自相矛盾要到展示时才发现 |
  | 开放题按「答案不含关键词」判错 | 制造假缺口；计划因此多教已会的内容 |
  | 领域层内置 LLM 判官 | 领域层依赖模型，破坏分层（ADR-0015） |
- **测试结果如何？**
  - `tests/test_learning_assessment.py`：18 个用例（映射、汇总从严、全对才算会、
    判不了不算判定、映射缺失不判定但保留证据并报告、降级两类分开、无降级时报告为
    空、降级不影响已判定结论、归一化匹配、开放题判不了、引用不存在题目被拒、
    题目标识重复被拒、判定与依据一致、未测知识点返回未判定、题目可不声明考点）。
  - `tests/test_learning_diagnosis.py`：17 个用例（迁移到证据模型）。
  - 全量：**748 passed**；`ruff` / `mypy` 全绿；十九个示例跑通。
  - `examples/learning_assessment.py`：映射 k1 会 / k2 缺口；两题全对 vs 一题答错；
    降级「判定 1 条、证据 2 条」；判官三态；两类错误被拒。
- **实践结果是否支持阅读材料中的观点？**
  支持两条：**判定要有依据**（不变量现在强制）；**判不了要说判不了**（`undecided`
  让「不知道」与「不会」分开）。
  **不支持**「严格汇总是合适的门槛」——阈值缺实证，这条被写进了 ADR 的风险项。

## 6. Reflection

1. **今天最重要的知识是什么？**
   **「信息不全」与「信息矛盾」必须分开处理。** 映射缺失是信息不全（降级：保留、
   报告、继续），判定与依据不一致是信息矛盾（错误：拒绝）。把它们混为一谈，
   要么让矛盾悄悄通过，要么让正常情况不断报错。降级报告不是「记录一下」，
   它是一个**一等的产品信号**——它告诉调用方「这次诊断有东西没覆盖到」。
2. **哪个观点改变或修正了原来的理解？**
   原以为「映射」是评估环节的工作——拿到题目与作答，评估去找对应知识点。实际上
   **映射是题目的属性**：出题时就知道这道题考哪个点。评估环节去「推断」映射，
   等于把一个本该确定的事实变成了猜测，而猜测无法审计。
3. **当前实现还有哪些局限？**
   严格汇总会高估缺口（无阈值依据）；精确匹配只适用客观题，Phase 1 若出开放题则
   诊断覆盖率低；证据类型只有做题一种（`EvidenceKind` 的其余取值尚无采集流程）；
   诊断结果没有持久化（ADR-0019 决定仓储层后置）；能力估计（连续掌握度）与薄弱
   点判定仍未建模。
