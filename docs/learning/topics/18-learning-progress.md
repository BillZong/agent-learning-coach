# Topic: Learning Progress

> Day 18 ｜ Phase 1 · Learning Core ｜ 主教材：—（本阶段无主教材章节） ｜ 外部参考：Knowledge Space Theory（Doignon & Falmagne）、Space of Learning（Masters）、掌握度学习（Bloom, 1968） ｜ 状态：已完成

## 1. Engineering Question

Learner Profile 与 Learning Progress 的区别是什么？进度应与知识点绑定，还是与计划任务绑定？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **画像与进度是两类不同的事实。** 画像回答「学习者是谁」（身份、背景、
    偏好），进度回答「学习者学到了哪」。两者的**变化频率**差几个数量级，
    因此不该放在同一个聚合里。
  - **知识状态是知识点集合的子集。** Knowledge Space Theory 的基本设定：
    学习者在某个知识空间上的状态，就是知识点集合的一个子集。状态因此
    **以知识点为对象**，而不是以「做了哪些步骤」为对象。
  - **知识状态对先修封闭。** 掌握了 `p` 就应当已经掌握 `p` 的全部先修。这条
    性质既是归因的理论依据（ADR-0016 已引用），也是进度数据的一致性约束。
  - **「执行状态」与「认知状态」是两回事。** 一个任务做完不代表对应的概念
    被掌握；跳过一步更不代表什么也没学到。把两者混在一套状态机里，
    「进度」就失去了可解释性。
  - **已有知识不需要独立概念。** 「本来就会」是学习过程里最早的一次状态
    变化，与「后来学会」在同一份记录里，靠先后与来源区分即可。

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  状态以知识点为对象；先修封闭是硬约束；进度是**位置**而非**步骤记录**；
  「跳过任务」与「没掌握概念」必须分开。
- **哪些观点存在分歧？**
  - **进度的分片单位。** KST 与「Space of Learning」都把状态看成「学习者 ×
    知识空间」的一个子集——即按**课程**分片。本项目第一版实现按 `goal_id`
    分片，实现时立刻撞上「同一个知识点在两个目标里要记两次」。这印证了
    文献的取向。
  - **是否要独立的「已有知识」模型。** 许多教学系统把入学诊断的结果单列为
    「先备知识」，与后续学习记录分开存。本项目把它放进同一条迁移序列——更
    简单，但代价是「已有」与「学过」的区别依赖迁移的**位置**，不是独立字段。
  - **状态粒度。** KST 是集合语义（只有「在集合里 / 不在集合里」）， mastery
    learning 要求分级。本项目取三档离散状态，是**范围取舍**而非理论结论。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**应用场景与设计目标**：诊断与学习记录是否分开，取决于系统是否
  需要独立演进「入学能力」这条线；本项目 Phase 1 还没有独立的产品界面来
  承载这个区分，因此选简单的一侧。
- **哪些结论缺少充分证据？**
  - **「三档状态够用」。** 「学了一半」与「完全没学」在进度里都是
    `in_progress`。这是真实的精度损失，没有实验支持「三档够用」。
  - **「按课程分片」在跨课程学习时是否够。** 知识点跨课程身份留给 Topic 22，
    在那之前，一个学习者在两门课里学的同一概念会被记成两个知识点——这是
    ADR-0016 已知且接受的后果。
  - **封闭性是否总是成立。** 现实中学习者可能先学会后学的部分（直觉上更
    容易），本项目把它当作**不一致**报出来。这条规则的强度没有实验依据。
- **哪些观点不适用于当前项目？**
  - **概率知识空间（PKS）与完整的掌握度分布**：需要大规模题目数据，Phase 1
    没有。
  - **连续掌握度分数**：属于掌握度模型（Topic 43）。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/learning/progress.py`**（新增）：
    - `LearningProgress`（实体）：`learner_id`、`course_id`、`points`；身份是
      （学习者 × 课程）这一对，**不设独立进度标识**。
    - `PointProgress`（值对象）：`point_id`、`transitions`；状态**由迁移历史
      派生**。
    - `PointTransition`（值对象）：`source`、`target`、`source_kind`
      （`assessed` / `learned`）、`reason`（必填）、`at`（调用方传入）。
    - `LearningState`：`not_started` / `in_progress` / `learned`。
    - 迁移：`start()` / `assess()` / `complete()` / `review()`——**每条边只有
      一个操作语义**。
    - 派生查询：`goal_completion()`、`ready_points()`、`blocked_points()`。
  - **`core/learning/consistency.py`**：新增 `check_progress_against_course()`，
    检查课程一致、知识点存在、**前置封闭性**（已学会的点的直接前置也必须已
    学会）。
  - **`core/learning/__init__.py`**：导出新符号。
  - **`tests/test_learning_progress.py`**：24 个用例。
  - **`examples/learning_progress.py`**：归属、状态机、已有知识、派生查询、边界
    五段演示。
- **为什么这样设计？**
  - **进度不进 Learner**：画像与进度变化频率差几个数量级，且多目标会互相
    污染——与 ADR-0015「Learner 不持有目标列表」同一条论证。
  - **按（学习者 × 课程）分片**：知识点身份是课程内的（ADR-0016），知识状态
    也是学习者在一个知识空间上的子集；按目标分片会让同一事实存两份。
  - **绑知识点不绑任务**：任务可跳过、可重建，身份不稳定；且「掌握了吗」
    不由「哪些步骤做完了」回答。
  - **知识点没有「跳过」也没有「受阻」**：跳过是任务能做的事；被阻塞是结构
    事实（前置没学会），存成状态就要同步更新所有下游点——双写。
  - **已有知识是迁移序列的第一条**：不需要额外概念，也不会让同一事实存两份。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 进度挂进 `Learner` | 每学一个知识点改一次学习者；多目标互相污染 |
  | 进度按 `goal_id` 分片 | 同一门课的知识点状态在多个目标间重复——双写 |
  | 进度引用任务 id | 重规划一次进度丢一次；粒度与知识点不对齐 |
  | 复用 `TaskStatus` | 「跳过一个任务」被误当成「掌握了一个知识点」 |
  | 知识点加 `skipped` 状态 | 「没学过」与「跳过了」不可区分 |
  | 知识点加 `blocked` 状态 | 前置变化时要同步更新所有下游点——双写 |
  | 单列 `PriorKnowledge` 概念 | 同一事实存两份；且诊断与学习的先后关系丢失 |
  | 进度进 `GoalSpec` | 运行时开始认识学习领域概念；契约归属被侵蚀 |
  | 派生查询只遍历已记录的知识点 | 「现在该学什么」的答案是空的 |
- **测试结果如何？**
  - `tests/test_learning_progress.py`：24 个用例，覆盖归属（进度不进 Learner、
    同一知识点只有一条进度）、状态机（三档状态、状态派生、复习、断链与非法
    迁移、每条边一个操作语义）、已有知识（判定与学会的区分）、派生查询（完成
    度、阻塞、可以学什么）、边界（跨课程拒绝比较、前置封闭性、进度不进
    `GoalSpec`）。
  - 全量：**675 passed**；`ruff` / `mypy` 全绿。
  - `examples/learning_progress.py`：归属与「学习者身上没有进度字段」；两类
    非法操作被拒并给出「该用哪个操作」；已有知识的首条迁移来源为 `assessed`；
    完成度 0% → 50%；阻塞与可学列表随进度变化；封闭性检查报出
    `prerequisite_not_learned`。
- **实践结果是否支持阅读材料中的观点？**
  支持两条结构层结论：进度按知识点组织确实更容易回答「哪些没掌握」「现在
  该学哪个」「哪些还动不了」；已有知识不需要独立概念。**不支持**「三档状态
  够用」与「封闭性总是成立」——前者是精度损失，后者是尚未检验的规则强度。
  这与前几个主题一致：机制可验证，效果需要实验。

## 6. Reflection

1. **今天最重要的知识是什么？**
   **「同一件事的两份说法」比「缺少一个概念」更危险。** 实现时我先想的是
   加一个 `PriorKnowledge` 概念表示已有知识，写完发现：它与「后来学会」是同一
   个知识点的两种来历，用迁移序列的第一条就够，**单列概念反而让同一事实存了
   两份**。这已经是本项目第三次遇到同一个病（目标的自由文本约束、关系的两种
   归属、这里的已有知识），也第三次用同一条药方解决：**先问「这个事实有几份
   说法」，再问「需要几个概念」**。
2. **哪个观点改变或修正了原来的理解？**
   原以为「进度」天然按目标分片——一个目标一份进度，不是挺清楚？实际上按
   目标分片会让同一门课的知识点状态重复存；而按课程分片后，「这个目标完成了
   多少」变成**查询**而不是**存储**。这提醒我：聚合边界不是按「用户想按什么
   维度看」划的，是按「哪个事实只存一份」划的。
3. **当前实现还有哪些局限？**
   三档状态没有「部分掌握」；封闭性作为硬规则报出，但现实中先学后学的部分
   很常见，这条规则可能过严；进度按知识点整体重建，知识点多时成本上升；
   跨课程同一概念仍是两个知识点；不变量仍只在内存校验。
