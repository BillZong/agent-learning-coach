## 1. Engineering Question

课程文档导入支持哪些格式？导入失败时应整批回滚，还是允许部分成功？

## 2. Primary Reading

- Book: —（本阶段无主教材章节）
- Chapter / Section: —
- 核心观点：
  - **一份坏文件不该毁掉整批**——但**静默的部分成功比整批失败更糟**（它让人以为
    材料齐了）。所以：部分成功 + 失败必须进报告。
  - **「不支持的格式」与「读不了的文件」是两回事**：前者要换工具，后者要修文件。
  - **导入要幂等**：id 由来源推导，重复导入是覆盖而不是追加；内容没变就不写。
  - **重新导入只更新材料本身**，不该顺手抹掉人工标注（课程侧的知识点关联）。
  - **材料的身份是全局的**，课程归属是它的属性——一份材料不能同时属于两门课。

## 4. Compare and Challenge

- **不同资料有哪些一致观点？**
  批量处理要部分成功；失败要可见；要幂等；解析器按类型选。
- **哪些观点存在分歧？**
  - **「不支持的格式」算不算失败。** 有的系统直接忽略（当噪声），本项目算**失败**
    并给出明确原因——教师需要知道「这份材料没进来，因为格式不支持」，否则他会以为
    系统漏了它。
  - **材料与课程的关系是一对多还是一对一。** 多数课程系统允许一份材料出现在多个
    课程里（引用）。本项目选择**一对一**（材料属于一门课），理由是「材料在整个
    系统里只有一个身份」与 id 由来源推导这条更简单的规则。分歧来自**身份模型**。
  - **要不要保留材料的历史版本。** 有的系统做「版本化文档」（Git 式的教材演进）。
    本项目当前是覆盖——理由是材料的变更由「重新导入」表达，而**计划**才需要保留
    历史（因为要回答「计划为什么变了」）。分歧来自**要回答的问题不同**。
- **分歧来自应用场景、设计目标还是技术演进？**
  主要来自**身份模型**与**要回答的问题**。
- **哪些结论缺少充分证据？**
  - **知识点关联要不要自动做**：判断「这份材料讲的是哪个点」要模型打分（Topic 46），
    本主题只提供显式关联。教师手工标注的比例有多高？不知道。
  - **材料存两遍（课程侧 + 切片侧）的成本**：材料量小时无所谓，大量材料时翻倍。
  - **Word 格式有没有真实需求**：不做是基于「还没验证有需求」，不是基于「不需要」。
- **哪些观点不适用于当前项目？**
  - **分布式导入与并行摄取**：单人教练，几十份材料。
  - **增量解析与内容差分**：当前是整份重解析。
  - **OCR**：扫描件直接跳过，不做识别。

## 5. Engineering Practice

- **实现了什么？**
  - **`core/learning/documents.py`**（新增）：`CourseDocument`（实体）、`DocumentKind`、
    `document_id`（与 RAG 侧同一套算法）、`infer_kind`。
  - **`core/rag/loader.py`**：新增 `PdfFileLoader`（PyMuPDF）、`NotebookFileLoader`、
    `load_source`（按扩展名分派，返回「文档 + 失败原因」）；`DirectoryLoader` 扩展到
    支持全部格式；`DocumentLoader` 协议加上 `skipped`。
  - **`core/application/ingestion.py`**（新增）：`DocumentRequest`、`IngestionReport`、
    `IngestionFailure`、`IngestionIssue`、`ingest_course_documents`。
  - **持久化**：`CourseDocumentRepository`（协议）+ 内存实现 + codec +
    `migrations/0002_course_documents.sql`。
  - **`tests/test_document_ingestion.py`**（新增）：20 个用例。
  - **`examples/document_ingestion.py`**（新增）：五段演示。
- **为什么这样设计？**
  - **部分成功 + 失败清单**：沿用 RAG 侧口径（ADR-0011）；但静默的部分成功比整批
    失败更糟，所以清单必须在报告里。
  - **课程文档是独立实体**：导入一份材料不该重写整门课（ADR-0015）。
  - **解析只做一次**：加载器在 `core.rag.loader`，课程侧只加课程归属与知识点关联。
  - **id 由来源推导**：重导一遍是安全操作。
  - **关联三种语义**（不改 / 清空 / 设置）：重新导入材料不该抹掉标注。
  - **一致性问题只报告**：材料本身是好的，只是标注错了。
  - **正文允许首尾空白**：那条规则是给标识符与短标签的。
- **有哪些替代方案？**
  | 替代方案 | 结果 |
  | -------- | ---- |
  | 导入失败就整批回滚 | 一份坏文件毁掉整个课程库 |
  | 静默跳过失败的文件 | 让人以为材料齐了——比整批失败更糟 |
  | 把课程文档放进 `Course` 聚合 | 导入一份材料就要重写整门课 |
  | 课程文档与 RAG 文档合成一个类型 | 两边形状与生命周期不同，合成会让两边都别扭 |
  | 自动关联知识点 | 判断「讲哪个点」要模型打分（Topic 46）；显式关联先立住 |
  | 重新导入时覆盖知识点关联 | 「重导一遍更新教材」会静默清空标注 |
  | 保留材料的历史版本 | 材料的变更由重导表达；需要历史的是**计划** |
  | 支持 Word | `python-docx` 只在 notebook 组；为未验证的需求加重量 |
  | 扫描件做 OCR | 当前直接跳过；识别质量与成本都没评估 |
  | 正文也套用「不允许首尾空白」 | 文件末尾通常有换行；正文要按原样保存 |
- **测试结果如何？**
  - `tests/test_document_ingestion.py`：20 个用例（文本 / 代码 / 笔记本 / PDF 解析；
    不支持的格式、文件缺失、空文件、扫描件、坏 JSON 都被拒并给出原因；导入、
    部分成功、幂等、内容变了更新、重新导入保留关联、显式清空关联、跨课程归属
    被拒、不存在的知识点被报告但不阻止导入、种类可覆盖、报告摘要）。
  - **DDL 在真实 PostgreSQL 18 上验证**：`migrations/0002` 干净应用；逐条确认
    CHECK 与外键拒绝坏数据（非法种类、负载 id 与列不一致、课程不存在、同 id 重复）。
  - 全量：**870 passed**；`ruff` / `mypy` 全绿；二十四个示例跑通。
- **实践结果是否支持阅读材料中的观点？**
  支持三条：**部分成功 + 失败可见**；**幂等导入**；**按类型选解析器**。
  **修正**一条：本来以为「不允许首尾空白」是领域层的通用规则。实现时撞上——那条规则
  来自「标识符的空白是调用方的错误」，**正文不是**：文件末尾通常有换行，正文按原样
  保存才是对材料的忠实。**规则要按字段的语义分，不是一律套用。**

## 6. Reflection

1. **今天最重要的知识是什么？**
   **静默的部分成功比整批失败更糟。** 「一份坏文件不该毁掉整个课程库」这个口径
   本身没错（RAG 侧早就这么定了），但它只说了「不要整批失败」，没说「不要静默」。
   部分成功如果**没有失败清单**，效果与整批失败一样——甚至更糟：整批失败会让人知道
   出了事，部分成功让人以为材料齐了。**部分成功必须配一份看得见的失败清单。**
2. **哪个观点改变或修正了原来的理解？**
   原以为「允许部分成功」和「整批回滚」是两个对立选项，选一个就行。实际上还有
   第三个维度：**哪些失败该整批拒绝**——课程不存在时没法谈「导入了哪些材料」，
   那是前置条件错误，不是某份材料的问题。
   另一处修正：**「不允许首尾空白」不是通用规则**。它来自标识符的语义（空白是调用
   方的错误），套到正文上就错了。
3. **当前实现还有哪些局限？**
   知识点关联只能手工给（自动关联属 Topic 46）；Word 不支持；扫描件跳过不做 OCR；
   材料的历史版本不保留；材料归属一对一，没法「一份材料进两门课」；正文存两遍
   （课程侧 + 切片侧）；SQL 适配器仍未实现；没有从 URL 导入。
